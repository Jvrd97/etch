# Контракт быстрых отметок для плавающего окна

Документ описывает всё, что нужно Swift-коду окна (`#159`, `#170`), чтобы его
написали, не читая `app/crud/quick_mark.py`. Два вызова, одно правило опроса и
одна названная вслух дыра в безопасности.

Источник истины по устройству кнопок — ADR-0018. Здесь только провод.

## Два вызова

### `GET /api/v1/quick-marks?surface=agent&date=YYYY-MM-DD`

Весь список того, что рисовать. `date` необязателен: без него сервер отвечает
за свой текущий день по границе суток (`local_date()`), и это правильный ответ
— окно не должно считать дату само, иначе между полуночью и четырьмя утра оно
разойдётся с приложением.

`surface=agent` оставляет только кнопки с `show_in_agent = true`. Значения
`web`, `agent`, `ios`; любое другое — **422**, а не полный список.

Поля каждой кнопки:

| Поле | Тип | Что это |
| --- | --- | --- |
| `id` | int | Единственное, что окно посылает обратно при тапе |
| `label` | string | Подпись, которую ввёл человек |
| `icon` | string \| null | Имя глифа; окно решает, чем его рисовать |
| `color` | string \| null | `#rrggbb` |
| `kind` | string | `increment` \| `check` \| `set_value` \| `relapse` |
| `step` | number \| null | Сколько прибавляет один тап; у галки пусто |
| `unit_label` | string \| null | Подпись единицы: «мл», «стр» |
| `hotkey` | string \| null | Один символ; в окне не используется |
| `order` | int | Порядок сверху вниз |
| `entry_date` | date | День, состояние которого в ответе |
| `today_total` | number \| null | Сумма дня; у галки всегда `null` |
| `done` | bool | День считает кнопку выполненной |
| `planned` | bool | Кнопку называет план дня (`#130`) |
| `plan_item_id` | uuid \| null | Пункт плана, который её назвал |
| `show_in_agent`, `is_active` | bool | Состояние переключателей |

**Порядок считает сервер.** Плановые кнопки идут первыми, внутри каждой
половины сохраняется порядок справочника. Окно не сортирует: тот же порядок
рисует веб, и второй порядок в окне был бы порядком, которого больше нигде нет.

### `POST /api/v1/quick-marks/{id}/events`

Тап. Тело:

```json
{ "source": "agent", "occurred_at": "2026-10-31T09:00:00Z", "utc_offset_minutes": 120 }
```

`occurred_at` окно шлёт всегда: это момент нажатия, и он же решает день, если тап
доехал позже. `value` необязателен, окно его не шлёт: применяется `step` кнопки; для галки `0` —
«снять галку». `utc_offset_minutes` хранится, но не слушается: он объясняет
тап, сделанный за границей, и никогда не решает, в какой день тот попал.

Ответ несёт новое состояние — `today_total`, `done`, `entry_date`, — поэтому
**окно перерисовывает ряд из ответа и второй `GET` не делает**. Заголовок
`Idempotency-Key` повторный тап не удваивает: тот же ключ отвечает `200` и тем
же событием вместо `201`.

Коды: `201` — записано; `200` — повтор по `Idempotency-Key`; `404` — кнопки
нет; `409` — кнопка выключена либо присланный `entry_date` не совпал с днём
сервера.

## Что рисует окно

Не больше четырёх кнопок в порядке, который прислал сервер, и пятая позиция —
«ещё». «Ещё» стоит всегда, при любом числе отметок, и открывает в браузере
`/quick-marks` на том же адресе сервера, с которым говорит агент. У кнопки
глиф (`icon`: имя SF Symbol, эмодзи или первая буква подписи), подпись и итог дня
с единицей; шаг показывает подсказка. Галка рисуется «✓» или «–»; повторный тап по
выполненной галке её не снимает: отмена в окно не входит.

## Опрос, а не подписка

Вебхуков и push не будет. VPS доступен только через Tailscale (ADR-0003),
публичного входа нет, и сервер до окна дотянуться не может в принципе.
WebSocket-канал не заводится по той же причине: он потребовал бы держать
соединение через tailnet, который рвётся вместе с Wi-Fi.

- **Интервал опроса — 15 секунд**, пока окно видно. Скрытое окно не опрашивает
  вовсе: ряд кнопок за спиной никому не нужен.
- **`ETag` обязателен.** Ответ `GET` несёт заголовок `ETag`; следующий запрос
  посылает его в `If-None-Match` и получает `304` без тела, если не изменилось
  ничего — ни справочник, ни состояние дня. Отпечаток берётся с выдачи целиком,
  поэтому чужой тап с телефона окно увидит.
- **Tailnet недоступен.** Окно не показывает ошибку и не гасит кнопки: оно
  оставляет последнюю известную картинку и помечает её устаревшей («данные не
  свежие» — после 60 секунд без ответа). Тап при недоступном сервере
  **копится в очереди на диске** и уезжает позже (#170, решение поверх первой
  редакции этого документа, где очереди не было). Это безопасно по времени:
  тело тапа несёт `occurred_at` — момент нажатия, и сервер кладёт событие в его
  день (`local_date(occurred_at)`; старше семи дней — 422, тап снимается с
  очереди). Повторная отправка идёт под тем же `Idempotency-Key`, поэтому
  потерянный ответ не удваивает событие: сервер отвечает `200` и тем же
  событием. Пока тап не подтверждён, кнопка считает его сама (итог + шаг) и
  рядом стоит пометка «не отправлено: N»; когда придёт ответ, кнопка рисует
  итог из ответа.
- **Что снимает тап с очереди без отправки:** `404` (кнопки нет), `409` (кнопка
  выключена или ключ чужой кнопки) и `422` — повтор дал бы тот же отказ. Окно
  говорит об этом строкой «сервер отклонил отметку». `401`, `5xx` и обрыв
  связи тап не снимают: ключ ротируют, сервер поднимают, сеть возвращается.
- **Очередь тапов** лежит в `quick-mark-taps.json` рядом с остальным состоянием
  агента, переживает перезапуск и уходит по одному, старые первыми. Паузы между
  попытками те же: 15 с → 30 с → 60 с.
- Повторные неудачи разводятся паузой: 15 с → 30 с → 60 с, дальше 60 с, пока не
  ответит.

## Ключ

`X-API-Key` обязателен на обоих вызовах. В проде ключ непустой, на стороне
агента лежит в Keychain (`#168`).

**Названный риск.** Пустой `API_KEY` в `core/auth.py` выключает проверку
целиком — не «пропускает», а именно выключает. Внутри tailnet это значит
открытый эндпоинт записи для всего, что попало в tailnet. Мириться с этим можно
только в разработке; пустой ключ в проде роняет старт (`#106`). Ключ у
веб-клиента — отдельный вопрос, `#109`.

## Чего в контракте нет

Заведения и правки кнопок: справочник редактируется на веб-экране
`/quick-marks`, окно только читает и тапает. Второй поллер окна — `GET
/agent/config` — живёт в `#159`, и почему их два, разобрано там.
