# Вход по passkey: как включить на сервере

Passkey работает только по HTTPS-имени tailnet (`https://<машина>.<tailnet>.ts.net`). По `http://100.121.220.42:3000` он не заработает ни в одном браузере: WebAuthn не принимает IP-адрес и незащищённую страницу. Пока переменные ниже не заданы, кнопок passkey нет, а вход по ключу работает как раньше. Решение и его границы — ADR-0022.

Нативное iOS-приложение passkey не получит: ему нужны Associated Domains с файлом AASA, который Apple забирает из публичного интернета, а хост только в tailnet ей не виден. Там будет Face ID на элементе Keychain — отдельный тикет iOS. Здесь — веб, включая Safari на iPhone.

## Исходная точка

Прод открывается по `http://100.121.220.42:3000`, в `habit-tracker/.env` стоит `BIND_ADDR=100.121.220.42`, код с `#205` влит в `main`.

## Шаги

1. **HTTPS в tailnet.** В админке Tailscale → DNS включены MagicDNS и HTTPS Certificates. Делается один раз на tailnet.
2. **Имя машины.** На сервере:

   ```bash
   tailscale status --json | jq -r .Self.DNSName | sed 's/\.$//'
   ```

   Ответ — например, `habit.tail1234.ts.net`. Дальше он стоит вместо `<имя>`.
3. **HTTPS-прокси на фронт.**

   ```bash
   tailscale serve --bg 3000
   tailscale serve status
   ```

   `status` должен показать `https://<имя>` → `http://127.0.0.1:3000`. Сертификат Tailscale выпустит сам при первом запросе.

   Фронт в `deploy/docker-compose.prod.yml` опубликован на двух адресах: `BIND_ADDR` (адрес tailnet, вход по http) и `127.0.0.1` (цель `tailscale serve`). `BIND_ADDR` не меняется, API на `:8000` остаётся на адресе tailnet — iOS-приложение и mac-агент ходят туда как раньше. Проверка после выката: `ss -tlnp | grep 3000` показывает и `100.121.220.42:3000`, и `127.0.0.1:3000`.
4. **Переменные.** Дописать в `habit-tracker/.env`:

   ```bash
   WEBAUTHN_RP_ID=<имя>
   WEBAUTHN_ORIGINS=https://<имя>
   # WEBAUTHN_RP_NAME=Habit Tracker   # имя в окне Face ID, по умолчанию такое
   ```

   `SESSION_COOKIE_SECURE` не трогать, если вход по `http://100.121.220.42:3000` ещё нужен: кука с `Secure` по http не сохраняется. Когда все устройства перешли на HTTPS-имя, поставить `true` — это строже.
5. **Выкат.** `make deploy` на сервере: подтянет код, пересоберёт образы, применит миграцию (таблица `webauthn_credential`) и поднимет контейнеры уже с новыми переменными.

## Проверка

- `curl -s https://<имя>/api/v1/auth/passkey/status` с машины в tailnet отвечает `{"enabled":true}`.
- Контейнер backend не стартует и в `make logs` есть строка про `WEBAUTHN_*` — значит, в паре чего-то нет, RP ID записан IP-адресом или origin не лежит под RP ID. Сообщение называет переменную.
- iPhone с включённым Tailscale, Safari → `https://<имя>/login` → войти ключом → «More» → «Passkey» → имя «iPhone» → «Добавить passkey» → Face ID. Ключ появляется в списке.
- «Выйти» → на `/login` кнопка «Войти по passkey» → Face ID → открывается приложение без ввода ключа. В списке у ключа появляется время использования.

На десктопе экран ключей открывается из меню: строка «Passkey» в разделе «Настройка» (`https://<имя>/settings/passkeys`).

## Как выключить

Убрать `WEBAUTHN_RP_ID` и `WEBAUTHN_ORIGINS` из `.env` и `make up`. Ключи в таблице остаются и снова заработают, если вернуть то же имя. Сменилось имя машины или tailnet — старые ключи бесполезны: удалить их в настройках и добавить заново.
