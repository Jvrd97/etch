# Изоляция CLI: один набор флагов на все четыре юзкейса

Каждый запуск `claude` из бэкенда собирается ровно в одном месте —
`app/llm/cli.py`, класс `IsolatedCli`. Через него ходят все четыре юзкейса LLM:
инсайты за период, онбординг категорий, разбор дня (`LLMClient.generate`) и
многоходовой чат (`ChatLLMClient.stream_turn`).

Тикет: `#111` (флаги появились), `#120` (распространены на `generate` плюс
смоук). Решение: ADR-0017, пункт 3.

## Что делают флаги

| Флаг / переменная | Что отрезает |
| --- | --- |
| `--tools ""` | модель ничего не исполняет: инструментов нет вовсе |
| `--setting-sources ""` | хуки, глобальный `CLAUDE.md`, чужие настройки, скиллы |
| `--strict-mcp-config` | MCP-серверы каталога конфигурации |
| `--system-prompt <свой>` | агентную преамбулу самого Claude Code |
| `CLAUDE_CONFIG_DIR` | личный `~/.claude` владельца машины |
| фиксированный cwd | случайный каталог запуска; он же ключ файла сессии CLI |

Замер ADR-0017 на CLI 2.1.250: **52 555 токенов** префикса первого хода без
флагов против **282** с ними. В одном из прогонов без изоляции модель
попыталась отработать личный скилл `/set` и написала об этом в ответе
пользователю.

MCP-серверы источниками настроек не считаются: они приезжают из
`<каталог конфигурации>/.claude.json`, и `--setting-sources ""` их не трогает —
`claude --help` отсылает за ними к отдельному `--strict-mcp-config`. В `#111`
этот флаг забыли, и смоук `#120` поймал это первым же живым прогоном: замер
2026-08-31 на той же CLI 2.1.250 — **21 620 токенов** первого хода без флага
против **290** с ним.

Набор перечислен в репозитории один раз — константа `ISOLATION_FLAGS` в
`app/llm/cli.py` (`ISOLATION_ARGS` — её плоская форма для командной строки).
Второй экземпляр означал бы юзкейс, тихо ходящий без изоляции: ответы остаются
правильными, меняется только цена и поведение.

## Версия CLI влияет на поведение флагов

`--setting-sources ""` проверен на CLI **2.1.250** и в общем списке опций описан
скупо. Обновление бинарника может вернуть 50-килотокенный префикс вместе с
личными хуками, и заметить это по ответам нельзя — они останутся правильными.
Поэтому обновление `claude` на сервере или на машине разработчика — повод
прогнать смоук, а не только посмотреть, что чат отвечает.

## Смоук

`services/backend/tests/test_cli_isolation_smoke.py` делает один настоящий
изолированный вызов и проверяет две вещи: вход первого хода
(`input_tokens + cache_creation_input_tokens`) ниже порога и в ответе нет следов
личной конфигурации хоста. Тот же смоук ловит обратную ошибку — чужой флаг,
отломавший запуск.

Порог — `MAX_FIRST_TURN_INPUT_TOKENS = 1000` при замере в 282 токена: запас
втрое на рост собственного системного промпта и ни одного порядка в сторону
преамбулы CLI. Поднимают его только вместе с намеренным ростом
`ONESHOT_SYSTEM_PROMPT` и только в этом файле. Прыжок сразу в десятки тысяч —
это не порог мал, это изоляция отвалилась.

Смоуку нужны живой бинарник и подписка, поэтому в обычном `pytest` он
пропускается с причиной, а не падает. Включает его признак окружения:

```bash
cd services/backend
make smoke       # только смоук
make preflight   # check (линт, типы, alembic heads, тесты) + смоук
```

`make smoke` подставляет `LLM_CLI_SMOKE=1`, личный `~/.claude` как
`CHAT_CLAUDE_CONFIG_DIR` и каталог в `/tmp` как `CHAT_CLI_CWD`. Личная
конфигурация рядом — и в префикс не попадает; это самая сильная форма проверки.
На сервере каталоги задаются переменными `SMOKE_CONFIG_DIR` и `SMOKE_CWD`.

Аутентификация смоука идёт только через `CLAUDE_CODE_OAUTH_TOKEN`. Явный
`CLAUDE_CONFIG_DIR` отключает тот вход, который бинарник нашёл бы сам (связка
ключей на macOS, смонтированный конфиг в контейнере) — то же самое предусловие
деплоя, что и у чата (`#119`). Без токена смоук пропускается с этой причиной, а
не падает.

`make preflight` — тот прогон, который идёт перед выкатом (`make deploy` в
`habit-tracker/`). В каждый локальный `pytest` смоук не входит намеренно: он
стоит живого вызова.

## Причины пропуска

| Причина | Текст в отчёте pytest |
| --- | --- |
| нет признака окружения | `LLM_CLI_SMOKE!=1: живой вызов CLI гоняется перед выкатом` |
| нет бинарника | `бинарника \`claude\` на этой машине нет` |
| нет подписки | `подписки нет: CLI отказал в аутентификации для <каталог>` |

Отсутствие подписки видно только по ответу CLI («Not logged in · Please run
/login»), проверить его заранее нечем: на macOS учётные данные лежат в связке
ключей, а не файлом в каталоге конфигурации. Любой другой ненулевой код выхода —
это падение, а не пропуск: так смоук ловит обратную ошибку, чужой или неизвестный
этой версии CLI флаг, отломавший запуск.
