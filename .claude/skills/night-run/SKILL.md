# Ночной прогон

Пока человек спит, тикеты идут по одному: сессия `claude -p` на тикет, внутри неё петля
`issue-loop.js`, после зелёных проверок — коммит в `phase-03` и перенос тикета в `done/`.
Утром отдельная свежая сессия ревьюит ночные коммиты и заполняет чек-листы.

Головой цикла работает bash, а не Claude. Claude вызывается внутри — как сессия на тикет
и как утренний ревьюер. Причина: падение одной сессии не должно убивать прогон.

## Запуск

```bash
bashs/issue-night.sh collect            # посмотреть, что возьмётся, ничего не запуская
bashs/issue-night.sh collect -n 20      # шире список
bashs/issue-night.sh run                # ночь целиком: волны + утреннее ревью
bashs/issue-night.sh run -n 3 --no-review
bashs/issue-night.sh review             # только ревью, по готовым отчётам
bashs/issue-night.sh review <ref>       # ревью от произвольной точки истории
```

Переменные окружения: `NIGHT_MODEL` (по умолчанию `opus`), `NIGHT_BUDGET` (12 долларов на
сессию тикета), `NIGHT_REVIEW_BUDGET` (15 на утреннее ревью), `NIGHT_REVIEW_MODEL`.

`run` не начнётся, если:

- в PATH нет `claude`, `node` или `python3`;
- ветка не `phase-03`;
- `habit-tracker/` грязный — иначе утренний дифф смешает чужую работу со своей;
- сегодня или **завтра** no-code день (`~/.claude/nocode/config`, сейчас `days=2,4`).
  Проверяются оба дня: прогон, начатый вечером понедельника, после полуночи упрётся в
  хук `nocode-guard` на первом же `Write` в `habit-tracker/` и выродится в ночь из BLOCKED.

## Что происходит за ночь

1. **Сбор** (`bashs/night-collect.py`). Кандидаты — `issues/PHASE-03/{backlog,in-work}/*.md`.
   `in-work` обязателен: там лежат тикеты, брошенные прошлой ночью. Отсев:
   - `**Type**` не `AFK` (то есть human-in-the-loop);
   - в «Vertical Slice Layers» есть строка `Mac:` или `iOS:` — петля Swift не собирает,
     каталога `habit-tracker/mac` не существует, такой тикет закроется молча наполовину;
   - номер уже упомянут в истории ветки как `PHASE-03/<N>` (волна B закрыла #90 и #93,
     а файлы остались в `backlog/` — preflight вернул бы already-done, сжёг бы агента);
   - есть незакрытый блокер. Блокер закрыт = его файл лежит в `done/`. Ищется глобом
     `issues/PHASE-*/{backlog,in-work,done,rejected,concerns}/N-*.md` — **без `PRDs/`**:
     там своя нумерация (`01-`, `02-`), которая один раз уже сломала триаж;
   - по тикету уже лежит финальный вердикт в `.night/results/<id>.json`. Сбросить —
     удалить этот файл.

   Порядок внутри волны — по оценке: `S`, потом `M`, потом `L`. Топологического порядка
   внутри волны не бывает по построению: тикет попадает в волну, только когда все его
   блокеры уже в `done/`, значит связей внутри набора нет. Топологию задают волны.
   Потолок `-n` по умолчанию 6: при одной сессии за раз ночь закрывает 4-6 тикетов.

2. **Волны** (`issue-night.sh run`). После каждой волны сбор идёт заново: тикет, чей
   блокер только что уехал в `done/`, становится доступен. Останов — когда список
   повторился: те же тикеты дважды значит остальное ждёт человека, а не нас.

3. **Тикет** (`bashs/issue-watcher.sh`). Тикет переезжает в `in-work/` до старта сессии,
   иначе следующая волна соберёт его снова. Сессия получает промпт: ШАГ 0 — прочитать
   `handoff/<id>.md`, если он есть; ШАГ 1 — запустить `issue-loop.js` через `Workflow` и
   дождаться его конца; ШАГ 3 — записать `.night/results/<id>.json`. Коммит и перенос
   тикета сессия НЕ делает.

4. **Коммит** делает bash, после того как сам прогонит проверки тронутых слоёв
   (ruff, ruff format, mypy --strict, одна alembic-голова, pytest; на фронте — bun test,
   tsc, lint). Зелёные → `git add -- habit-tracker`, один коммит
   `<commitSubject из результата>` с телом `Refs PHASE-03/<id>`, тикет → `done/`.
   Красные → коммита нет, тикет остаётся в `in-work/`, статус `BLOCKED_CHECKS`,
   работа уезжает в `git stash`.

5. **Дерево остаётся чистым после каждого тикета.** Всё, что не закоммичено, уходит в
   `git stash push -u -m "night-<дата> <id> <причина>" -- habit-tracker`. Работа не
   теряется (`git stash list`), но следующий тикет не строится поверх чужого недоделанного
   диффа. Это прямое следствие того, что worktree здесь нет.

6. **Утро** (`issue-night.sh review`). Одна свежая сессия — намеренно свежая: ночные
   сессии не должны судить сами себя. По каждому тикету: прочитать
   `.claude/loop-reports/<id>.json`, прочитать коммит, пройти шесть линз (соответствие
   тикету, корректность, миграции, контракты, приватность, тесты), пройти чек-лист по
   пунктам `ok|fail|skip` с `file:line`, засечь `elapsedSec` и `diffLines`, записать
   `.night/reviews/<id>.json`, влить его командой `night-report.js review`.

## Где смотреть утром

| что | где |
|---|---|
| сводка ночи | `docs/PHASE-03/night-run/<дата>/night.md` |
| страница тикета | `docs/PHASE-03/night-run/<дата>/<id>.md` |
| отчёт петли как есть | `.claude/loop-reports/<id>.{json,md}` |
| статус сессии и коммит | `.night/results/<id>.json`, `.night/summary.tsv` |
| почему тикет не взяли | `.night/night-<дата>.dropped.tsv` |
| журнал переносов тикетов | `.night/moves.tsv` и таблица в сводке |
| проверки перед коммитом | `.night/logs/<id>.checks.log` |
| сырой конверт сессии | `.night/logs/<id>.attempt<N>.json` |
| конспект прерванной сессии | `.night/handoff/<id>.md` |
| что было в issues/ до ночи | `.night/backlog.before-<дата>.txt` |

Пересобрать сводку руками: `node bashs/night-report.js night --date 2026-08-31`.

## Сбои

**Переполнение контекста.** Сессия сама пишет `handoff/<id>.md` (что сделано, какие файлы
в каком состоянии, какие проверки красные, точный следующий шаг) и результат со статусом
`CONTINUE`. Watcher видит `CONTINUE` и запускает не resume, а чистую сессию — она стартует
с ШАГА 0, то есть с конспекта. Порог «контекст больше половины» — эвристика в тексте
промпта, другой защиты от обрыва посреди работы нет.

**Падение API.** `rc != 0` → `resume` того же `session_id` не больше двух раз подряд,
потом чистая сессия. Пауза между попытками `30 × номер попытки`.

**Сессия завершилась чисто, но без результата.** На практике это «запустила фоновый
Workflow и ответила „жду“, убив его вместе с собой». Resume повторил бы то же ожидание,
поэтому следующая попытка идёт в режиме `direct`: петля проводится инлайном, без Workflow.

**HTTP 429.** Первый же 429 ставит `.night/ratelimit.stop`: квота у аккаунта общая,
остальные тикеты упрутся в ту же стену. Прогон останавливается целиком и печатает, когда
лимит снимется. Снять флаг — удалить файл.

## Права: чем рискуем

Ночь идёт с `--dangerously-skip-permissions`. Без него не обойтись: `acceptEdits`
подтверждает только правки файлов, а первая же Bash-команда вне allow-списка поднимает
промпт разрешения — отвечать некому, сессия висит до бюджета. В `ask` у нас лежат ровно
те команды, без которых ночь не проходит: `alembic upgrade head`, `alembic downgrade*`.

Цена честная: флаг снимает и `deny` тоже. Ночная сессия технически может выполнить
`rm -rf`, `sudo`, `git push --force` и цель `make f-git` корневого `Makefile`
(`git add .` + `git push origin main`). Держат её три вещи, и все они мягкие: текст
промпта (скоуп `habit-tracker/`, запрет push, cd, worktree и make), то, что коммит делает
не агент, а скрипт, и то, что ветка `phase-03` не `main`. Не устраивает — `--ask-perms`
и человек рядом; автономного прогона тогда не будет.

Отдельно, `.claude/settings.json` ночь НЕ правит: там значения для дневных сессий
человека. `CLAUDE_SKIP_FEEDBACK_CHECK=1` и `BASH_DEFAULT_TIMEOUT_MS=600000` watcher
экспортирует себе сам. Стоит рассмотреть (решение человека, не скрипта): добавить
`Bash(make f-git)` в `deny` и перенести `Bash(env *)` из gitignored `settings.local.json`
в `settings.json` — сейчас именно эта строка отделяет прогон от зависания на первом
pytest, а файла с ней в git нет.

## Чем отличается от alv-версии и почему

| alv | здесь | почему |
|---|---|---|
| `-j 5`, лок на сервис | одна сессия за раз, один глобальный лок | worktree сняты намеренно (мало места), тикеты вертикальные, скоуп у всех `habit-tracker/`. Две петли в одном дереве перетопчут файлы, тесты и `git add` |
| round-robin по каталогам сервисов | порядок по оценке S → M → L | сервисов нет, выводить их не из чего |
| `service_of()`, `role_block()` | удалены | то же самое: одна роль, один скоуп |
| коммит и `mv` делает агент | делает bash после своих проверок | петля по контракту не коммитит; `git add .` затянул бы `.claude/loop-reports/`, который не в `.gitignore` |
| `backlog → in-work → in-review → done` | `backlog → in-work → done` | папки `in-review` в этом проекте нет |
| блокер закрыт в `done/` или `in-review/` | только `done/` | то же |
| id вида `auth-open-02` | голые числа | другая конвенция имён |
| frontmatter `type:`/`blocked_by:` | markdown-шапка `**Type**:` | здесь frontmatter нет ни у одного тикета (читалка всё равно двухформатная — в alv одноформатное чтение один раз собрало в прогон тикет с пометкой «НЕ БРАТЬ») |
| `night-report.js` на 864 строки, HTML, doc-граф, сервер 8931 | Markdown, 300 строк | графа нет, `docs-html/` нет, сервера нет. Понадобится страница — `/academic-html` отрендерит готовый `.md` |
| отчёты в `docs/REPORTS/` + `docs-html/` | `docs/PHASE-03/night-run/<дата>/` | `docs/` в git, `issues/` — нет; отчёт обязан пережить `rm -rf issues/` |
| `swarm-board.py`, `swarm-watchdog.py`, доска 8932 | не переносились | доска фактов нужна параллельным сессиям, а сессия одна. Надзиратель ловит зависшую сессию, отнимающую слот, — слот один и он же виден в `.night/live/` |
| скилл `code-review` в утреннем промпте | шесть линз выписаны в промпте | скилла `code-review` в `~/.claude/skills/` нет, звать по имени нечего |
| `git mv` тикета, перенос виден в истории | обычный `mv`, журнал в `.night/moves.tsv` и в сводке | `issues/` первой строкой в `.gitignore` |

## Границы

- Прогон не делает `push` и не трогает `main`.
- Прогон не правит `issues/` иначе как переносом файла тикета между lifecycle-папками.
- `issue-swarm.js` ночью не используется: его фаза Triage — один агент на все тикеты, и
  весь прогон живёт в одной сессии, падение которой убивает работу целиком. Он остаётся
  ручным инструментом дня на пачку 2-5 тикетов.
- Запуск ночи — решение человека. Автозапуска по расписанию нет.
