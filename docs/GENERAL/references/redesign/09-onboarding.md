# Экран 9 — Onboarding (голосовой конструктор категорий)

Статус: редизайн не начат. Экран новый и осознанно **web-only**: даже после выхода iOS
он остаётся в вебе (зафиксировано в ADR-0004).

---

## 1. Назначение

Свернуть самую тяжёлую часть входа в продукт: вместо ручного создания двадцати категорий с полями
пользователь описывает словами, что хочет отслеживать, LLM собирает план, пользователь его правит
и применяет одним нажатием.

## 2. Что на экране сейчас

Заголовок `Конструктор.` плюс «Опишите словами, что хотите отслеживать — получите план и создайте
выбранное одним нажатием.»

Большое текстовое поле с плейсхолдером «Например: хочу трекать сон — сколько часов и качество,
и добавить пульс в спорт». Кнопка генерации.

Далее — список карточек операций плана. Каждая карточка:
- Чекбокс «применять эту операцию».
- Для новой категории: редактируемое имя, строка «form · build · Спорт», список полей
  с типом и признаком обязательности. При совпадении имени с существующей категорией —
  предупреждение «имя уже занято».
- Для добавления поля: «Новое поле в категории #12» и описание поля.

Внизу — применение выбранных операций; после успеха происходит переход в список категорий.

Экран русскоязычный.

## 3. Данные

- `POST /onboarding/draft { transcript }` → план операций. Возможны две операции:
  `create_category` (с полным набором полей и флагом конфликта имени) и `add_field`
  (в существующую категорию). План — **только превью**, на сервере ничего не сохраняется.
- `POST /categories/batch { operations }` — применение: либо все операции ложатся одним коммитом,
  либо ни одна.
- План **только additive**: удалять и переименовывать существующее он не умеет принципиально.
- Структурированный вывод текстовый (JSON внутри ответа модели) с валидацией и одним ремонтным
  заходом — native tool use не используется, потому что он есть только на одном из двух бэкендов.

## 4. Проблемы текущего экрана

- Название «Конструктор» и голосовой сценарий из PRD не совпадают с тем, что на экране:
  голоса нет, есть текстовое поле. Диктовка оставлена системной клавиатуре.
- Операция `add_field` показывается как «Новое поле в категории **#12**» — идентификатором,
  а не именем категории.
- Нет превью результата: пользователь видит список полей, но не видит, как категория будет выглядеть
  на Today или в таблице.
- Редактировать можно только имя категории. Тип поля, обязательность, группу, режим — нельзя,
  только принять или отключить целиком.
- Конфликт имени показывается предупреждением, но пути разрешения (переименовать, слить, пропустить) нет.
- Экран живёт в глубине «More» на мобильном и в конце навигации на десктопе, хотя это точка входа
  в продукт для нового пользователя.
- Нет примеров и подсказок: пустое поле не объясняет, насколько подробно надо описывать.
- Генерация занимает время, состояние ожидания минимально.

## 5. Ограничения

- План строго additive: изменения и удаления вне сценария.
- Нет истории планов: сгенерированный и не применённый план теряется.
- Нет записи голоса в самом приложении.
- LLM-слой возвращает JSON текстом, поэтому возможен ремонтный заход и, в худшем случае, отказ.

## 6. Чего ждём от редизайна

- Внятный первый экран продукта: как выглядит вход, когда категорий ещё ноль.
- Превью того, что будет создано, в терминах интерфейса, а не в терминах модели данных.
- Редактирование плана целиком, а не только имени.
- Разрешение конфликтов имён как явный выбор.
- Честное состояние ожидания генерации.
- Место сценария в навигации: отдельный вход для новичка против пункта в «More» для опытного.
