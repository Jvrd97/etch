# Экран 5 — Category detail (страница одной привычки)

Статус: редизайн не начат. Самый содержательный аналитический экран из существующих.

---

## 1. Назначение

Всё про одну привычку: динамика, серия, полная история записей, быстрое добавление.

## 2. Что на экране сейчас

Хлебная крошка «← Categories». Заголовок — название категории с лаймовой точкой, ниже описание.
Справа — стрелки «предыдущая / следующая категория» и кнопка «New entry».
Ниже — горизонтальная лента чипов со всеми категориями для быстрого переключения.

**Блок серии** (только для `streak_mode='avoid'`): текущая серия, лучшая серия, дата последнего срыва.

**График** (`CategoryChart`, Recharts) — два режима в зависимости от типа категории:

| Тип | График |
|---|---|
| Чек-лист | Столбцы: сколько пунктов из N отмечено в каждый день. Лаймовые столбцы со скруглением |
| Форма с number/time-полями | Линии, по одной на поле. До двух осей Y, автоматическое назначение единиц (секунды приводятся к минутам). Легенда с возможностью скрыть серию. Режимы «за день» и «накопительно» |

Периоды: 7 / 30 / 90 дней и «всё». Палитра серий проверена на контраст для тёмной поверхности.

**История записей**: группировка по дате, внутри — карточки записей с полями и значениями,
редактированием и удалением.

Пустое состояние: «No entries yet».

## 3. Данные

Один батч при открытии: `GET /categories/{id}`, `GET /categories` (для пагинации и ленты чипов),
`GET /table` за год (данные графика), `GET /entries?category_id` (лимит 1000, пагинации нет),
`GET /categories/{id}/streak`.

График строится **из агрегатов `/table`**, а не из сырых записей — то есть точка на графике это
дневная сумма, посчитанная сервером.

## 4. Проблемы текущего экрана

- График занимает много места, но ничего не объясняет: нет среднего, нет тренда, нет сравнения
  с прошлым периодом, нет выделения рекордов и провалов.
- Нет ни одного числа-итога: за период не видно ни суммы, ни среднего, ни числа активных дней.
- Серия показывается только для avoid-категорий, для всех остальных блок просто отсутствует.
- История — плоский список без пагинации: при годе истории это тысяча карточек.
- Лента чипов со всеми категориями плюс стрелки пагинации плюс хлебная крошка — три способа
  навигации в одной шапке.
- Значения без единиц.
- Переключатели периода на графике не связаны с историей ниже: график за 30 дней, история — за всё.

## 5. Ограничения

- Нет целей, поэтому на графике нечего рисовать линией нормы.
- Нет сравнения периодов на сервере — «vs prev 30d» считается на клиенте.
- Нет серий для build-категорий.
- `GET /entries` без пагинации.
- Единиц измерения нет; для `duration` есть форматирование в часы и минуты.

## 6. Чего ждём от редизайна

- Итоговые числа за выбранный период рядом с графиком: сумма, среднее, активных дней, рекорд,
  дельта к прошлому периоду. Это то, ради чего на экран заходят.
- Связка периода: один селектор на весь экран, а не отдельно на графике.
- Что показывать для build-привычки вместо блока серии.
- Работа с длинной историей: свёртка по месяцам, ленивая подгрузка, календарный вид.
- Единая шапка навигации вместо трёх параллельных механизмов.
- Мобильная раскладка: график, итоги и история на узком экране.
- Согласование со строкой из блока Trends на утверждённом дашборде: тап по тренду ведёт сюда,
  и цифры на обоих экранах обязаны сойтись.
