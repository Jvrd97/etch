# Экран 2 — Today

Статус: редизайн не начат. Это второй по важности экран после дашборда — именно он обслуживает
главный сценарий «записал за ≤3 тапа».

---

## 1. Назначение

Экран текущего дня: всё, что нужно отметить сегодня, одним списком, с отметкой в один тап.
Не история и не аналитика — только «сделай сейчас».

## 2. Что на экране сейчас

Заголовок `Today.` и подзаголовок «`2026-07-30` — one tap to check things off» (дата в сыром ISO-формате).

Категории раскладываются на три группы, каждая со своим способом отображения. Раскладку делает
чистая функция `partitionTodayCategories`:

| Группа | Условие | Как выглядит |
|---|---|---|
| Streaks | `streak_mode='avoid'` | Карточка на всю ширину: иконка огня, название, крупное число дней лаймом, «N days clean», дата последнего срыва, кнопка «Записать срыв» с раскрывающейся формой (значение плюс заметка) |
| Чек-листы | `display_mode='checklist'` с boolean-полями | Секция с названием категории, внутри — чипы-таблетки по одному на поле. Активный чип лаймовый с галочкой |
| Quick input | остальные категории с number-полем | Строка: название, суммарное значение за день, кнопка `+`; тап по строке открывает полный редактор записи за сегодня |

Пустое состояние: «Nothing to track today — Create a checklist category or a form category with a number field».

Мобильный двойник `/m/today` — та же логика, своя разметка, крупнее зоны тапа.

## 3. Данные и поведение

- Загрузка: `GET /categories` плюс `GET /entries` за сегодня; для каждой avoid-категории отдельный
  `GET /categories/{id}/streak`.
- Отметка чек-листа: `PUT /entries/checklist` — upsert за день.
- Инкремент числа: `POST /entries` с одним значением.
- Обе мутации **оптимистичные**: UI меняется сразу, при ошибке откатывается ровно на ту величину,
  которую добавил конкретный тап. Дневная сумма пересчитывается из записей, а не хранится отдельно.
- Экран сам обновляется, когда вкладка снова становится видимой (`useRefreshOnVisible`).
- Тап по карточке быстрого ввода открывает **сегодняшнюю** запись категории, если она есть, а не
  создаёт новую: день таких тапов должен углублять одну запись, а не плодить дюжину.
- Прямо сейчас добавляется колонка `show_in_today` — явное решение пользователя, показывать ли
  категорию здесь; `null` означает «решай эвристикой» (описанной в таблице выше).

## 4. Проблемы текущего экрана

- Дата в подзаголовке — сырая ISO-строка `2026-07-30`, не человеческая.
- Нет ощущения дня: не видно, сколько из ожидаемого уже отмечено, нет никакого индикатора прогресса.
- Три группы визуально разнородны: карточка на всю ширину, чипы, строка — три разных языка на одном экране.
- У числовых значений нет единиц: «42» без «повт.».
- Шаг инкремента у кнопки `+` захардкожен и одинаков для воды и для отжиманий.
- Ничего не сообщает о том, что было вчера — нельзя понять, «пропустил или ещё не сделал».
- Порядок категорий — это порядок из API, пользователь его не контролирует.

## 5. Ограничения (детали в общем контексте, §5)

- Нет целей — «3 из 5 привычек» посчитать можно только как «есть запись / нет записи», а не как норму.
- Нет расписания привычек: система не знает, что бег ожидается по вторникам.
- Нет единиц измерения и нет шага инкремента у поля.
- Стрики есть только для avoid-категорий, для build их нет вообще.
- Стрики запрашиваются по одному.

## 6. Чего ждём от редизайна

- Единый визуальный язык карточки привычки вместо трёх разных.
- Внятный ответ на вопрос «что у меня с сегодняшним днём» в верхней части экрана.
- Порядок и группировка: что показывать первым, как обходиться с 22 категориями без бесконечной прокрутки.
- Поведение уже отмеченного: уезжает вниз, гаснет, схлопывается.
- Раскладка для широкого экрана (сейчас одна колонка) и для мобильного.
- Согласованность с утверждённым дашбордом: блок «Продолжить трекинг» на дашборде и этот экран
  показывают одни и те же привычки — надо решить, чем они отличаются и не дублируют ли друг друга.
