# Комплект брифов для редизайна интерфейса

Материалы для внешнего дизайн-запроса (ChatGPT). Каждый запрос собирается из двух файлов:
**общий контекст плюс бриф нужного экрана**. Общий контекст не дублируется в брифах намеренно.

| Файл | Экран | Статус редизайна |
|---|---|---|
| `00-common-context.md` | Продукт, модель данных, API, дизайн-система, ограничения | преамбула, прикладывается всегда |
| `01-dashboard.md` | Dashboard | **макет утверждён**, разобран против бэкенда |
| `02-today.md` | Today | не начат |
| `03-table.md` | Table | не начат |
| `04-categories.md` | Categories (список и редактор) | не начат |
| `05-category-detail.md` | Страница одной категории | не начат |
| `06-entries.md` | Entries | не начат |
| `07-journal.md` | Journal | не начат |
| `08-insights.md` | Insights | не начат, задет макетом дашборда |
| `09-onboarding.md` | Onboarding | не начат |

Утверждённые макеты: `docs/design/dashboard-design-desktop.png`, `docs/design/dashborad-design-mobile.png`.

Каждый бриф устроен одинаково: назначение экрана, что на нём сейчас, какими данными он живёт,
проблемы текущей версии, ограничения модели данных, чего ждём от редизайна.
Раздел «ограничения» важнее остальных: он не даёт нарисовать то, что нечем наполнить.
