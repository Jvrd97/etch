# Экран 6 — Entries (все записи)

Статус: редизайн не начат.

---

## 1. Назначение

Плоская лента всех записей по всем категориям с фильтром и редактированием.
Фактически «сырые данные» приложения.

## 2. Что на экране сейчас

Заголовок `Entries.` плюс «Track your daily data» и кнопка «New entry».
Ниже карточка-фильтр: один `select` «All categories» и список категорий.

Лента: группировка по дате (заголовок — сырая ISO-дата лаймовым капслоком), внутри — карточки записей.
Карточка показывает категорию, значения полей и позволяет отредактировать или удалить запись.

Пустое состояние: «Nothing here yet — Start tracking by creating your first entry».

**Редактор записи** — модалка на десктопе, полноэкранная шторка на мобильном:
выбор категории (или заблокированная категория, если пришли из контекста), дата, поля по типам
(число, текст, чекбокс, дата, время, select, длительность), заметка. Открывается по глубокой
ссылке `?new=1` — так дашборд и другие экраны попадают сразу в редактор.

## 3. Данные

- `GET /entries` — весь список, без пагинации; фильтр по категории применяется запросом.
- `GET /categories` — для фильтра и редактора.
- `POST` / `PATCH` / `DELETE /entries/{id}`.
- Группировка по дате делается на клиенте чистой функцией.
- У записи есть `idempotency_key` для дедупликации повторной отправки из офлайн-очереди.

## 4. Проблемы текущего экрана

- Экран не отвечает ни на один вопрос: это дамп таблицы БД в обратном хронологическом порядке.
- Фильтр — единственный `select` по категории. Нет фильтра по датам, по группе, по наличию заметки.
- Даты — сырые ISO-строки, без «Сегодня» и «Вчера».
- Нет пагинации и нет виртуализации: сто записей уже длинно, тысяча — неработоспособно.
- Не видно времени записи, хотя `created_at` есть.
- Значения без единиц.
- Дублирование с историей на странице категории: там та же лента, только отфильтрованная.

## 5. Ограничения

- `GET /entries` не умеет ни сортировку, ни курсор — только `skip`/`limit`.
- Нет полнотекстового поиска по заметкам.
- Нет времени события, есть только `created_at`.

## 6. Чего ждём от редизайна

- Ответ на вопрос, зачем этот экран нужен рядом с Today, Table и страницей категории —
  возможно, он должен стать «журналом всех действий» или, наоборот, схлопнуться.
- Человеческие даты и группировка (Сегодня / Вчера / на этой неделе), как на макете дашборда
  в блоке «Недавняя активность» — там уже утверждён нужный вид ленты.
- Фильтры, которые реально применяют: период, категория, группа.
- Работа с объёмом: пагинация или бесконечная лента.
- Единая карточка записи, согласованная с лентой на дашборде и историей на странице категории —
  сейчас это три разных вида одной сущности.
