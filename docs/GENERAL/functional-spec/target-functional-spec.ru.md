**КОРОТКО**

**habit_tracker_ai — личное рабочее место одного человека.** Начинался как трекер привычек со своими категориями. С 2026-08-30 стал «CTO workspace»: в Postgres живут план дня с правилами и вердиктом «день выигран», быстрые отметки, челленджи, время по ролям, входящие из ClickUp. Чат с Claude видит эти данные и предлагает изменения, применяет их человек. Основной интерфейс — браузер на маке. На телефоне работают мобильная веб-версия `/m` (PWA) и нативное iOS-приложение со старым набором экранов. Сервер — FastAPI и Postgres на VPS, доступ только через Tailscale.

**На 2026-10-01 из 47 функций готовы 27, частично работают 13.** Четыре есть только на сервере: приём HealthKit, предложения челленджей от ИИ, режим дня и обратная запись в ClickUp (последняя — в ревью). Три не начаты: Gmail, Telegram, обязательства из писем. Ядро трекера, план дня, вердикт, чат, быстрые отметки, челленджи и роли работают от экрана до базы.

## 1. Что это за продукт

**Для кого.** Один пользователь — владелец, CTO. Многопользовательского режима нет и не планируется: в базе нет таблицы пользователей и колонки `user_id`, доступ закрыт одним ключом (ADR-0003, ADR-0014).

**Что делает.** Держит в одной базе весь день: что запланировано, что сделано, сколько ушло на работу, что с телом, что пришло из внешних систем. Считает, выигран ли день, по правилам, которые человек задаёт сам. Даёт ИИ доступ к этим данным, но без права писать: модель предлагает, человек нажимает «применить».

**Как менялся.** PHASE-00 — веб-MVP трекера. PHASE-01 — iOS-приложение, мобильная веб-версия, AI-инсайты, разбор дня. PHASE-02 — контур здоровья, открыт, сделана серверная половина. PHASE-03 (активная) — «CTO workspace»: файловая система personal-os переехала в Postgres, появились план дня, чат-агент, роли, входящие и агент на маке. PHASE-04 — виджеты и уведомления, только идея.

**Три рамки, которые действуют на всё:**

- **Ручной ввод первичен.** Отметку, подтверждённую человеком, автоматика не перезаписывает: ни разметка ролей, ни пересчёт челленджа, ни импорт.
- **ИИ предлагает, человек применяет.** Модель не исполняет инструменты и не пишет в базу. Удаление и правка прошлого в её схеме ответа невыразимы; единственное исключение — переписать план дня целиком (ADR-0021).
- **Тел сообщений не храним.** Из писем и задач сохраняются заголовок и ссылка; агент на маке отправляет только идентификатор приложения и время. Скриншотов, OCR, записи экрана нет и не будет.

## 3. Ядро трекера

Ядро — PHASE-00 и PHASE-01: категории, записи, стрики, таблица, журнал, дашборд. Работает в вебе, в `/m` и в iOS. Последние правки — явное главное поле категории, единицы и шаги быстрого ввода (#175, #176), лента активности (#76).

### 3.1 Динамические категории и поля — Готово — `categories`, `fields`

**Это главная фишка продукта.** Человек сам заводит, что отслеживать: «Сон», «Вода», «Отжимания», «Сахар». У категории — свои поля любого из восьми типов: текст, число, да/нет, дата, дата-время, время, выбор из списка, длительность. Новая категория не требует миграции базы: схема хранения одна на все категории (EAV — сущность, атрибут, значение).

**Что настраивается у категории:**

- имя, описание, цвет, группа (вкладки в таблице);
- вид ввода: форма (`form`) или чек-лист (`checklist`, нужен хотя бы один флажок);
- смысл серии: «делаю» (`build`) или «избегаю» (`avoid`);
- показывать на Today: авто, всегда, никогда;
- главное поле — оно попадает в таблицу и графики; без явного выбора берётся первое по порядку;
- «активна»: выключенная категория скрывается, история остаётся.

**Что настраивается у поля:** тип, обязательность, значение по умолчанию, варианты выбора, единица (`мл`, `км`), шаги быстрого ввода (`+250`, `+500`), порядок. Порядок меняется стрелками с озвучкой для скринридера.

**Три способа создать.** Форма «New category». Голосом или текстом через конструктор (§4.1): модель предлагает категории и поля, человек отмечает нужные. Пакетом через `POST /categories/batch`: всё или ничего.

**Правка без потери истории.** Форма отправляет полный список полей. Поле со своим `id` обновляется на месте, и его значения сохраняются. Новое поле создаётся. Поле, убранное из списка, удаляется вместе со значениями.

**Чего нет.**

- Сервер не проверяет значение по типу поля, обязательность и значение по умолчанию: проверку делает только форма.
- Имя категории уникально на всю базу.
- Варианты выбора хранятся строкой через запятую, хотя модель описывает их как JSON.
- Поле «дата-время» в вебе вводится обычным текстом.
- В iOS при создании нельзя выбрать чек-лист или «избегаю» и нельзя добавить поле в существующую категорию.

**Готовность: готово.** Встроенных шаблонов категорий «из коробки» пока нет (#178).

### 3.2 Записи — Готово — `entries`, `entry_values`

Запись — значения полей категории на дату плюс заметка. Создать можно из Today, страницы категории, таблицы, ленты, разбора дня, чата и быстрой отметки. Правка и удаление есть везде, где запись видна.

Повторная отправка той же записи не создаёт дубль: клиент шлёт `Idempotency-Key`, первый запрос отвечает 201, повтор — 200 с той же записью. Так работает офлайн-очередь iOS.

Значения при чтении приводятся по типу поля: истина — `true`, `1`, `yes`; число каноничное (`30.0` → `30`). В таблице числа и длительности суммируются, флажки дают «хоть одно да», остальное — последнее значение.

**Готовность: готово.** Ограничение: `GET /entries` без параметра отдаёт 100 последних записей, и iOS-экраны History и Dashboard больше 100 не видят.

### 3.3 Чек-лист-категории — Готово — `display_mode=checklist`

Категория-чек-лист — набор флажков на день: «Витамины», «Растяжка», «Без сахара». Тап по флажку сразу ставит или снимает галку (оптимистично, с откатом при ошибке). Одна запись на категорию и дату; повторная отправка обновляет её, а не создаёт новую (`PUT /entries/checklist`).

На странице категории — столбцы «X из N» по дням и серия по каждому флажку. Разбор дня и чат умеют ставить галки, но не снимать.

**Готовность: готово.**

### 3.4 Стрики воздержания — Готово — `streak`

Для категорий «избегаю» (`avoid`) считается серия чистых дней: «12 дней без сахара, лучший — 30». Срыв — флажок «да» или число больше нуля. День без записей считается чистым. Кнопка «It happened» записывает срыв с количеством и заметкой, отменить можно сразу.

Дашборд показывает текущие серии; запрос идёт одной пачкой по всем категориям.

**Чего нет.** Серии «делаю подряд» (`build`) нет: режим хранится, но счёт идёт по формуле воздержания.

**Готовность: готово.**

### 3.5 Экран Today — Готово — `/today`, `/m/today`, iOS Today

Главный экран веба. На нём:

- строка быстрых отметок с горячими клавишами (§6.1);
- карточки серий воздержания;
- чек-листы;
- быстрый ввод чисел шагами `±N`;
- записи за сегодня с правкой;
- челленджи (§6.2);
- кнопка «Спросить про день» — открывает чат.

На `/m/today` добавлена большая кнопка «Рассказать день»: речь распознаёт браузер (Web Speech, ru-RU), дальше работает разбор дня (§4.2). В iOS Today — карточки категорий и формы, офлайн-очередь и бейдж «N ждут отправки».

**Чего нет и что сломано.**

- Today пишет запись по дате браузера, а план и быстрые отметки — по границе суток сервера. С 00:00 до 04:00 они расходятся на день. iOS-Today делает ту же ошибку.
- Быстрые отметки запрашиваются дважды. Используемый тап идёт без `Idempotency-Key` и без повтора, хотя правильная функция с ключом в коде есть.

**Готовность: готово, с двумя багами выше.**

### 3.6 Таблица «дни × привычки» — Частично — `/table`

Сетка: строки — дни, колонки — главные поля категорий, вкладки — группы. Галку чек-листа можно поставить задним числом. Тап по пустой ячейке открывает форму записи, по заполненной — записи дня с правкой и удалением.

**Чего нет.** Окно — жёстко 14 дней, листания назад нет (в iOS — 30 дней и кнопка «старше»). Редактор ячейки в вебе понимает только число и текст и удаляет без подтверждения. На `/m/table` ячейку можно только дополнить.

**Готовность: частично.**

### 3.7 Лента записей и журнал — Частично — `/entries`, `/journal`

`/entries` — одна лента записей трекера и журнала по датам, с фильтром по категории. `/journal` — свободный дневник: заголовок, дата, настроение, текст в Markdown, теги через запятую.

**Чего нет.** Обе ленты показывают 50 последних записей без «ещё». Поиск, фильтр по настроению и датам в API есть, на экране нет. В iOS журнал нельзя редактировать, только создать и удалить.

**Готовность: частично.**

### 3.8 Дашборд — Готово — `/dashboard`

Кольцо «сколько записано сегодня», последняя запись, текущие серии, «продолжить отслеживание», AI-разбор периода с выбором 7/30/90 дней (§4.3), три KPI, лента активности, быстрые действия.

**Чего нет.** Структурного AI-отчёта на дашборде (#77) и блока трендов (#78) нет. Тикет #80 (настройки, иконки, перевод интерфейса) ждёт решения владельца: период анализа 7 или 30 дней.

**Готовность: готово.**

### 3.9 Страница категории — Готово — `/categories/[id]`

График за период: линия для форм, столбцы и серии для чек-листов, режимы «по дням» и «накопительно». Блок серии воздержания. Лента записей с правкой в карточке. Переход к соседним категориям стрелками. В iOS — то же на Swift Charts.

**Готовность: готово.**

## 4. AI-функции

Модель вызывается двумя путями: подпроцессом `claude -p` с изоляцией или через Anthropic API. Выбор — переменная `LLM_BACKEND` или автоматически. Если ни один путь не настроен, AI-ручки отвечают 503, а генерация плана переходит на детерминированный каркас. Модель не исполняет инструменты: ответ — текст или JSON, который сервер проверяет схемой и смыслом.

### 4.1 Конструктор категорий из текста — Готово — `/onboarding`

Человек пишет или диктует: «хочу следить за водой, сном и тренировками». Модель видит существующие категории и предлагает операции «создать категорию» и «добавить поле». Сервер проверяет тип каждого поля, наличие флажка у чек-листа, существование категории и повтор имён; конфликт имени помечается на карточке. Человек отмечает нужное, может переименовать, и всё создаётся одной транзакцией.

**Чего нет.** Микрофона на экране нет, хотя функция называлась «голосовым конструктором». Модель не заполняет оформление категории целиком (#81) и не причёсывает существующие (#82).

**Готовность: готово.**

### 4.2 Разбор дня из пересказа — Готово — `/daily-summary`, `/m/today`

Человек рассказывает день своими словами. Модель возвращает план записей: числа по полям (длительность в секундах, калории с пометкой «оценка»), галки чек-листов, текст в журнал. Каждая строка помечена флагами «оценка», «не уверен», «неправдоподобно». Сервер сам решает, дописать текст в существующую запись журнала или создать новую. Нераспознанное показывается отдельно.

Применение — одна транзакция с ключом идемпотентности. Повторное нажатие ничего не дублирует, гонка двух нажатий ловится на уровне базы. Исходный текст сохраняется до вызова модели (`transcripts`).

**Чего нет.** Распознавания речи на сервере нет и не будет: голос распознаёт устройство (решение 2026-07-26, тикет #51 отклонён). Чек-лист и журнал в плане разбора пока необязательны (#83).

**Готовность: готово.** Тестов — 89.

### 4.3 AI-разбор периода — Готово — `/insights`, дашборд

Кнопка на дашборде запускает разбор за 7, 30 или 90 дней. Модель получает дневные агрегаты всех активных категорий и до 200 записей журнала. Отчёт — Markdown на русском: «Тренды», «Пропуски», «Корреляции», «Рекомендации». Отчёты сохраняются, история открывается на `/insights`. В iOS — то же, с таймаутом 120 секунд.

**Готовность: готово.**

### 4.4 Чат с Claude — Готово — `/chat`, `/m/chat`

Многоходовой разговор, ответ печатается потоком (SSE). Что видит модель:

- **Карточку дня** — правила дня числами, план, отметки, итог. Ограничена 20 000 символами; при переполнении выбывают строки наименее важного раздела, и модель видит пометку «не поместилось N строк».
- **Выборки по запросу.** Модель может попросить данные из белого списка: записи за период, журнал, здоровье по дням, серию категории, срез таблицы, задачи из входящих. До 92 дней, до 500 строк, до двух заходов за ход. Каждая выборка пишется в журнал аудита.

Что модель может предложить: записать метрику, поставить галку, дописать журнал, собрать или переписать план дня. Предложение показывается плашкой с галочкой на каждой операции. «Применить» записывает выбранное через тот же путь, что разбор дня. После применения остальные плашки на ту же дату устаревают.

Видно, сколько потрачено токенов и сколько длился ход; блок мысли отделён от ответа; «Что чат видит» показывает карточку дня в том виде, как она ушла в модель. Разговор можно удалить; зависший ход — сбросить.

**Пределы.** Два одновременных хода на процесс сервера; лишний получает 429. Один ход на разговор; второй — 409. Ход ограничен 180 секундами, первые символы должны прийти за 30.

**Чего нет.**

- На проде чат не работает: для `claude -p` нужен `CLAUDE_CODE_OAUTH_TOKEN` (#119), живой вызов ни разу не проверялся (#182). Каталог сессий не смонтирован томом, поэтому продолжение сессии после перезапуска контейнера превращается в повтор всей истории — работает, но дороже.
- На `/m/chat` нет плашек, «Что чат видит», расхода и удаления. Удаление из списка в десктопе застряло после трёх раундов ревью (#197).

**Готовность: готово в коде.** Тестов — около 190.

### 4.5 Чат переписывает план дня — Готово — `rewrite_day_plan`

«Собери мне день» или «переделай день» — модель предлагает план целиком. Сервер сам называет операцию: `draft_day_plan`, если плана нет, `rewrite_day_plan`, если есть. План, нарушающий правила дня, снимается с плашки ещё до показа и проверяется повторно при применении. Отметки переносятся на пункты с тем же кодом. Повторное нажатие на применённую плашку — 409.

Это единственная операция, которой модель может что-то заменить (ADR-0021). Правку отдельной строки плана из чата не делаем.

**Готовность: готово.** Тестов — 16.

### 4.6 Предложения челленджей от ИИ — Только сервер — `llm/challenge_proposal.py`

Разбор ответа модели, проверка пары «категория + поле», запись предложения в статусе `proposed` написаны и покрыты тестами. Модуль никто не вызывает: нет ни вызова модели, ни эндпоинта генерации. Предложение можно создать вручную через `POST /challenges` с `origin=ai`, и Today покажет его с кнопками «принять» и «отклонить».

**Готовность: только сервер.**

## 5. День

Центр PHASE-03. День живёт в собственных таблицах Postgres, правила дня — версионированные данные, вердикт — чистая функция от плана, отметок и правил (ADR-0014, ADR-0015).

### 5.1 Граница суток — Готово — `core/daytime`

День идёт с 04:00 до 04:00 по Берлину. Отметка в 00:30 относится ко вчерашнему дню — в плане, отметках, сериях, интервалах и ролях. Часовой пояс и час начала берутся из действующей версии правил дня. Время без часового пояса сервер отвергает. В дни перевода часов сутки длятся 23 или 25 часов.

**Что расходится.** iOS-приложение и веб-Today считают «сегодня» по полуночи устройства (§3.5). Здоровье считает дату по смещению устройства с границей в полночь. Тикет #185 сводит оставшиеся места сервера к одной функции и лежит в ревью.

**Готовность: готово на сервере.**

### 5.2 Канон дня — Частично — `day_rule_set`, `/settings/day-rules`

Правила дня — строка таблицы с периодом действия, а не константы в коде. В правилах:

- потолок работы (480 минут), жёсткий потолок (540), «переработка проигрывает день» (600);
- время остановки работы (16:00);
- максимум задач (4) и учёбы (2), доля задач для победы (100%);
- края дня: подъём 06:00, старт работы 07:45, ревью 15:40, отбой 22:30;
- свободный вечер 19:10–21:00, вечер с близкими 18:30–21:00;
- обязательные якоря, рабочие дни, дни без кода, порядок условий вердикта, условие роли.

Прошлый день всегда судится той версией, под которой его прожили. Новая версия публикуется с завтрашнего дня или позже; пересечение периодов запрещает база. Править и удалять версии нельзя — только выпустить новую. На `/settings/day-rules` видна действующая версия, история и форма новой версии.

**Что сломано.** Публикация копирует в новую версию только часть полей. Края дня, свободный вечер, якоря, порядок вердикта, выходные и лимит учёбы получают значения по умолчанию, а не значения прошлой версии. Форма в вебе покрывает тоже не все поля.

**Готовность: частично.**

### 5.3 План дня — Готово — `day_plan`, `/day`

План — документ из секций и пунктов. Пункт бывает задачей, якорем, жёсткой точкой, свободным, минимумом и другими видами. У пункта есть окно `ЧЧ:ММ-ЧЧ:ММ`, жёсткость (`hard` / `soft` / `free`), критерий «сделано», ссылка на цель квартала, роль и вид акта, вложенные пункты.

**Правила документа** — сервер отказывает с указанием пункта:

- у задачи обязательны окно, критерий и цель квартала, либо причина «не связано с целью»;
- жёсткими могут быть только края дня;
- у свободного пункта нет окна;
- задач не больше лимита.

Окно через полночь (`23:30-00:30`) — это 60 минут. Наложения окон показываются. Человек правит пункт на месте: добавляет, удаляет, переносит.

**История правок.** Ревизия 0 — предложение машины. Дальше каждое изменённое поле пишется в журнал, и экран «диф» показывает, что поправил человек. Первая отметка дня замораживает план новой ревизией.

**Готовность: готово.** Тестов — 92.

### 5.4 Генерация плана — Частично — `/day/{date}/plan/generate`

Кнопка «Собрать план». Модель получает только числа из правил дня и флаги тренировки, без текста жалоб. Сервер проверяет ответ схемой и восемью правилами:

- жёсткие только края;
- свободный вечер пуст;
- сумма задач не выше потолка;
- задач и учёбы не больше лимита;
- здоровье до работы;
- в выходной есть вечер с близкими;
- окна не пересекаются;
- всё на целевую дату.

При нарушении модель получает один ремонтный заход — только коды правил и строк, без своего прошлого ответа. Не вышло, истекло 300 секунд или модель не настроена — день получает детерминированный каркас из правил с кодом причины. Каркас проходит все восемь правил по построению.

**Что не работает.**

- Ответ модели без единой фигурной скобки бросает исключение, которое не ловится, и запрос отвечает 500 вместо каркаса (`plan_flow.extract_json` → `ValueError`, а `parse_plan` ловит только `PlanError`).
- Модель не знает двух правил, по которым её судят: вечер с близкими и лимит учёбы. Отсюда лишние уходы в каркас.
- Сигналы дня и гейты тренировок в генерацию не передаются.
- Переносы задач со вчера — заглушка: каркас всегда получает пустой список.
- Генерация синхронная, в запросе, а не фоновой задачей. Фоновый вариант — #149 и #184.

**Готовность: частично.** Основной путь работает и покрыт 13 тестами; краевой случай с ответом без JSON падает. Сбой сборки плана в проде разбирает #198.

### 5.5 Ночной каркас — Готово — `worker`, `nightly_skeleton`

Воркер раз в сутки пишет каркас плана на завтра, если правило есть, завтра рабочий день и плана ещё нет. План помечается «требует проверки». Модель ночью не вызывается — это решение ADR-0015.

**Чего нет.** Задание запускается раз в 24 часа от старта воркера, а не в 03:00.

**Готовность: готово.**

### 5.6 Отметки пунктов и якоря — Готово — `plan_mark`, `day_anchor`

Клик по пункту гоняет состояние по кругу: пусто → сделано → не сделано. «Неактуально» — отдельная кнопка, такой пункт не идёт в знаменатель. К отметке можно добавить заметку. Каждая смена пишется в журнал событий, который переживает удаление пункта.

Якоря — обязательные края дня: подъём, спорт, старт работы, ревью, отбой, вечер с близкими. Отмечаются отдельным блоком или связанными пунктами плана. Знаменатель — состав якорей в правилах дня, а не число строк.

День считается «открытым», если на него зашли сегодня или вчера, — так отличается «не открывал» от «не сделал».

**Что расходится.** Вердикт требует вечер с близкими каждый день, где якоря отмечались. Правила плана и каркас требуют его только в выходные.

**Готовность: готово.**

### 5.7 Рабочие интервалы — Готово — `work_interval`

Человек отмечает начало и конец работы или пауз; интервал можно остановить, поправить, удалить. Минуты считаются только по рабочим интервалам; открытый интервал — до текущего момента. Нет ни одного интервала — «не измерено», а не ноль: такой день не проигрывает по переработке. Интервалы от агента на маке при первой ручной правке помечаются «исправлено», исходные границы сохраняются.

**Готовность: готово.**

### 5.8 Закрытие дня и вердикт — Готово — `day_summary`, `/day`

День закрывается в два касания: ревью около 15:40 и вечернее закрытие. Ревью можно пропустить. Каждое касание идемпотентно: повтор с тем же ключом ничего не меняет.

Вердикт «выигран / проигран» считается по условиям в порядке из правил дня:

1. **Переработка.** Минуты работы не выше потолка действующего профиля. «Не измерено» проходит.
2. **Якоря.** Все обязательные закрыты.
3. **Задачи.** Доля сделанных не ниже планки; без задач условие проходит.
4. **Роль.** В рабочий день без запрета на код был хотя бы один акт CTO или архитектора.

Проигрыш называет первое непройденное условие. Человек может переопределить проигрыш в победу, но только с запиской; в обратную сторону нельзя. Серия выигранных дней: победа — плюс один, проигрыш — ноль, воскресенье не меняет серию.

Импортированные из personal-os дни сохраняют свой вердикт и не пересчитываются.

**Готовность: готово.** Тестов — 89. Пересчёт истории на каждое касание делает около шести запросов на каждый закрытый день; с годами замедлится.

### 5.9 Профили потолка и долг — Частично — `day_rule_profile`, `overtime_debt`

Три профиля потолка работы:

| Профиль | Потолок / жёсткий (мин) | Когда |
|---|---|---|
| baseline | 480 / 540 | по умолчанию |
| deadline | 720 / 720 | перед дедлайном |
| recovery | 360 / 420 | восстановление |

Поднять потолок можно только с подтверждения человека. Каждая минута сверх базового потолка становится долгом. Долг гасится днём, который недоработал базовый потолок на всю сумму долга; частичного погашения нет. Неделя с непогашенным долгом не выиграна. Долг виден на экране недели.

**Что сломано.** Сервер должен сам предлагать поднять потолок: два длинных дня подряд и дедлайн в ближайшие три дня. Функция поиска дедлайнов всегда возвращает пустой список, поэтому предложение не появляется никогда.

**Готовность: частично.**

### 5.10 Отчёт дня — Готово — `day_report`

Отчёт «как прошёл день» собирается из базы: отметки, заметки, блокнот, тренировка, итог закрытия. Новая ревизия пишется, только если текст изменился. Пустой источник объясняет себя.

**Чего нет.** Источник «сигналы дня» — заглушка до #146. Время ревью «15:40» в тексте зашито строкой, а не берётся из правил.

**Готовность: готово.**

### 5.11 Неделя — Частично — `/week`

Неделя ISO: выигранные дни из всех, серия на конец недели, семь квадратов, воскресный чек-лист разбора, текст ретро, долг переработки, сводка по ролям.

**Чего нет.** В интерфейсе всё только для чтения: ретро и чек-лист пишет импорт из personal-os или API. Планирования недели как генератора нет.

**Готовность: частично.**

### 5.12 Цели и вехи — Частично — `/goals`

Уровни целей 0–5, десять вех M1–M10 с графом зависимостей, до пяти целей на квартал. Задача плана без связи с целью квартала требует причину — «чужая срочность».

**Чего нет.** Цели приходят из файла `goal.md` импортом. В интерфейсе меняется только статус вехи; цели квартала задаются через API.

**Готовность: частично.**

### 5.13 Тренировки — Частично — `training`

Состояние тела выводится из дней тренировок и жалоб: что было последним, сколько подходов на паттерн за неделю, сколько дней подряд пропущено. По нему из 12 упражнений предлагаются допустимые, с объяснением исключений:

- жалоба на эту область;
- тяжёлая тяга или жим менее 48 часов назад;
- 16 и больше подходов за неделю.

Два дня «до отказа» за неделю переводят в режим RIR 2–3. Два пропуска подряд дают RIR 3 и объём ×0,7.

**Чего нет.** На экране дня тренировка только читается: жалобы и рекорды есть в API, но не в интерфейсе. Гейты не доходят до генерации плана (§5.4). Чтение состояния пишет в базу.

**Готовность: частично.**

### 5.14 Сетка жизни — Готово — `/life`

Таймлайн в пяти масштабах: жизнь, год, месяц, неделя, день. Видно, сколько недель прожито и сколько осталось. Квадрат дня окрашен по состоянию и ведёт на день. Дата рождения и горизонт хранятся в браузере.

**Готовность: готово.** На `/m/life` ссылки ведут на десктопные экраны.

## 6. Быстрые отметки и челленджи

### 6.1 Быстрые отметки — Готово — `quick_marks`, `/quick-marks`

Кнопка «в один тап» привязана к полю категории. Четыре вида:

- **increment** — прибавить шаг (`+250 мл`);
- **set_value** — заменить значение;
- **check** — поставить или снять галку;
- **relapse** — записать срыв, каждый тап — новая запись.

Кнопки есть на Today, в окне агента на маке (по контракту, не реализовано) и в iOS (не реализовано).

На десктопе работают горячие клавиши. Цифры 1–9 — по позиции кнопки, своя буква назначается в редакторе. Буквы срабатывают и в русской раскладке. `?` открывает легенду. Клавиши молчат, когда открыт диалог или курсор в поле ввода.

Кнопки, которые назвал план дня, идут первыми. Тап по такой кнопке закрывает свой пункт плана, только вперёд. Последний тап кнопки можно отменить. Отмена откажет, если тап не последний или значение уже правили руками.

Справочник кнопок — `/quick-marks`: порядок, вид, шаг, единица, клавиша (занятая клавиша — 409 у поля), показ в агенте, активность. Ответ кэшируется по ETag, чтобы агент мог опрашивать раз в 15 секунд.

**Что расходится.** Пункт плана «2 л воды» закрывается первым стаканом: «сделано» означает «сумма больше нуля», цели у кнопки нет. Тап из веба идёт без ключа идемпотентности (§3.5).

**Готовность: готово.** Тестов — 73.

### 6.2 Челленджи — Готово — `challenges`, Today

Обязательство на окно до 92 дней по паре «категория + поле». Четыре вида правила: «не меньше N», «не больше N», «отмечено», «воздержание». Режим провала: «любой промах» или «бюджет промахов». День без данных — промах, а не «нет данных».

Жизненный цикл:

1. «Предложен» — от ИИ или плана.
2. «Активен» — после того как человек принял.
3. «Выигран» или «провален» — автоматически.
4. «Брошен» — вручную.

Человек может поставить вердикт дня руками; пересчёт его не перетирает и может вернуть проваленный челлендж в активные. Вердикты дней досчитываются при чтении, планировщик не нужен. Удалить категорию, у которой есть челлендж, нельзя.

**Готовность: готово.** Правка и пересчёт есть в API, но не на экране.

## 7. Роли и время на маке

### 7.1 Роли CTO — Готово — `/roles`, `/roles/rules`

Рабочее время раскладывается по ролям:

| Роль | Целевая доля |
|---|---|
| CTO | 25% |
| архитектор | 25% |
| тимлид | 50% |
| без роли | — |

Целевые доли подписаны как гипотеза. Две меры: минуты («куда ушёл день») и акты («случилась ли роль сегодня»).

Источники по старшинству: ручной ввод > план > ClickUp > git > активность на маке. Сильный источник забирает часы у слабого, одни часы не считаются дважды. Подтверждённую человеком строку автоматика не трогает.

**Правила разметки** — «паттерн → роль» семи видов: приложение, заголовок окна, путь репозитория, префикс коммита, список и тег ClickUp, секция плана. Перед сохранением правило обязательно прогоняется по истории: видно, у каких правил оно отберёт строки. Переразметка периода показывает доли до и после. Секция плана с ролью даёт минуты, пункт с видом акта при «сделано» создаёт акт.

Сводка за период — доли против целевых и сигнал «правила отстали»: больше 30% времени без роли за 30 дней.

**Что сломано.** Переразметка по данным агента переводит все неподтверждённые строки в «без роли». Образец для повторного сопоставления не восстанавливает идентификатор приложения, поэтому пробный прогон по ним никогда не находит совпадений. Тесты покрывают только git. Удалить акт из интерфейса нельзя. Коммиты и ClickUp как источники не подключены (#136, #146).

**Готовность: готово, кроме переразметки активности.**

### 7.2 Агент на маке — Частично — `habit-tracker/mac/HabitAgent`

Иконка в строке меню. Раз в 5 секунд и при смене приложения агент смотрит, какое приложение активно, и склеивает наблюдения в интервалы. Возврат в то же приложение в течение 30 секунд продолжает интервал. Пачки по 25+ интервалов уходят на сервер, ошибки повторяются с паузой от 30 до 600 секунд. Наружу уходят только идентификатор приложения и время. Незнакомые приложения сервер отсекает по каталогу. Интервалы видны на экране дня в блоке «Где прошёл день», их можно править и добавлять руками.

**Чего нет — почти всё из ADR-0019:**

| Чего нет | Тикет |
|---|---|
| Заголовки окон и правила приватности на маке (на сервере есть) | #156, #157 |
| Простой, блокировка, сон | #172 |
| Очередь на диске (сейчас в памяти, крэш теряет данные) | #163 |
| Пульс «агент молчит» | #164 |
| Плавающее окно с задачей и таймером | #159 |
| Режим дня | #162 |
| Быстрые отметки в окне | #170 |
| Метрики Claude Code | #165 |
| Упаковка и автозапуск | #167 |
| Экран настроек | #168 |

**Блокер.** Агент принимает только HTTPS или localhost, а прод внутри tailnet — `http://100.x`. Отправить на прод агент не может, решение за владельцем.

**Готовность: частично (скелет #155).**

### 7.3 Режим дня — Только сервер — `day_mode`, `mode_schedule`

Режим — вид дня (работа, выходной, отпуск, больничный) плюс флаг «без кода». Расписание по дню недели, ручное переопределение на дату. Нерабочий режим удаляет автоматическую разметку ролей за день. Сервер отдаёт режим агенту.

**Чего нет.** Экрана и переключателя нет (#162). Есть два расписания рабочих дней: правила дня и режим. Условие роли в вердикте смотрит на первое, разметка ролей — на второе.

**Готовность: только сервер.**

## 8. Входящие

Входящие — единый слой сигналов из внешних систем без тел сообщений (ADR-0016). Читаются только чаты, лейблы и списки, которые человек включил; пустой список означает «ничего не читаем».

### 8.1 ClickUp — Готово — `/inbox`

Карточка источника: ключ доступа (вводится один раз, назад не показывается, хранится зашифрованным), «включён», интервал, проба «что видно снаружи» без записи, ручной опрос. Лента сигналов со ссылкой на задачу. Чат видит задачи через выборку и при этом освежает источники с истёкшим интервалом.

**Чего нет.** Фонового опроса нет: опрос из воркера (#99) в ревью, в реестре заданий его нет. Наблюдаемость источников — #105. Мобильной версии экрана нет.

**Готовность: готово.**

### 8.2 Gmail, 8.3 Telegram, 8.4 Обязательства — Нет

Строки источников есть в справочнике, адаптеров нет: опрос отвечает 409 `no_adapter`.

- **Gmail** — письмо становится сигналом без тела, OAuth из интерфейса, рабочий ящик с allowlist лейблов (#100, #186).
- **Telegram** — один чат из allowlist, только чтение (#102).
- **Обязательства** — модель превращает сигнал в карточку «ты обещал ответить X до среды», человек принимает или отклоняет (#101).
- **Суточная ретенция** и тест-контракт приватности — #104.

Всем нужен вход, который делает человек.

### 8.5 Отметка «сделано» обратно в ClickUp — Только сервер

Таблица журнала обратной записи в базе есть. Сам код (#103) и тест идемпотентности (#204) в ревью и в `main` не влиты. Обратная запись — только «сделано» и только в личный ClickUp; полной синхронизации не будет.

## 9. Здоровье

### 9.1 Приём HealthKit на сервере — Только сервер — `POST /health/samples`

Сервер принимает сырые семплы 24 метрик в четырёх группах:

- **движение** — шаги, дистанция, этажи, энергия, упражнения, стояние;
- **сердце** — пульс, пульс покоя, вариабельность ритма, дыхание, SpO2, VO2max;
- **тело** — вес, жир, мышцы, ИМТ, рост;
- **питание** — калории, белки, жиры, углеводы, вода.

Единицы переводятся в каноничные; неизвестная единица отклоняет пакет целиком. Накопительные метрики делятся по часам пропорционально длительности. Дневное значение — сумма или взвешенное среднее. `GET /health/metrics` отдаёт дни за период до 366 дней; чат видит здоровье через выборку.

**Чего нет.** Отправителя нет: iPhone не вызывает `POST /health/samples` (#131). Нет фоновой доставки (#133), журнала синков (#132), годового бэкфилла, часовых графиков, тренировок и фаз сна (PHASE-02, #66–#72). Если семплы одного часа придут разными пакетами, часть потеряется: корзина часа перезаписывается.

### 9.2 Экран здоровья на iPhone — Частично

Вкладка Health в iOS запрашивает доступ на чтение при первом входе и показывает последнее значение каждой из 24 метрик или «Нет данных». На сервер ничего не уходит. Для шагов и калорий показывается последний кусок, а не сумма за день. Есть и сиротская веб-страница `/m/health`, на неё не ведёт навигация.

ADR-0020 решил, что iPhone — только «насос» данных, а экраны здоровья живут в вебе. Вкладка Health этому противоречит.

## 10. Клиенты

### 10.1 Веб на маке — Готово

Основной интерфейс. Next.js 16, React 19, 20 экранов. Навигация из одного реестра:

| Раздел | Экраны |
|---|---|
| День | Today, Day, Life, Week, Chat, Day summary |
| Данные | Dashboard, Roles, Входящие, Table, Entries, Journal, Insights |
| Настройка | Goals, Быстрые отметки, Categories, Day rules, Onboarding |

Скрытый экран — правила приватности заголовков окон (`/agent/title-rules`).

Данные перезагружаются при возврате на вкладку. Ошибки показываются рядом с действием. Модалки держат фокус и закрываются по Escape.

**Чего нет.** Страниц ошибки, «не найдено» и загрузки нет. Офлайна нет. Новый экран ежедневной работы (#199) ждёт выбора варианта: единый экран со связанными карточками или отдельные экраны.

### 10.2 Мобильный веб `/m` и PWA — Частично

Отдельная оболочка того же Next.js: шапка, нижние вкладки (Today, Entries, Dashboard, Categories, More), полноэкранные листы, которые не прячутся за клавиатурой iOS. Ставится на домашний экран как приложение и стартует с `/m/today`. Переключатель «Mobile» и «Desktop version» запоминается.

**Чего нет.**

- `/m/dashboard`, `/m/life` и ссылка на правила заголовков уводят в десктопную оболочку.
- Входящих и правил дня в мобильной версии нет.
- Чат без плашек; таблица только на добавление; день без выбора ролей.
- Приёмка на iPhone по чек-листу не проведена (#49).

### 10.3 iOS-приложение — Частично

SwiftUI, iOS 17, без внешних зависимостей, тёмная тема Lime Tech. Девять вкладок:

| Вкладка | Что делает |
|---|---|
| Dashboard | сводка |
| Today | формы, чек-листы, серии воздержания, срывы |
| Table | 30 дней с подгрузкой старше |
| History | правка и удаление записей |
| Journal | создание и удаление, без правки |
| Categories | создание, правка, страница категории с графиками |
| Insights | AI-разбор периода |
| Health | локальное чтение HealthKit |
| Settings | адрес сервера и ключ |

Ключ хранится в Keychain. Когда сеть пропадает, Today и Table показывают последний снимок с меткой времени. Новая форма на Today уходит в офлайн-очередь и отправляется при появлении сети, без дублей.

**Чего нет.**

- Ничего из PHASE-03: плана дня, быстрых отметок, чата, ролей, челленджей.
- Офлайн-очереди у чек-листа, срыва, быстрого ввода, правок.
- Записей, застрявших после пяти ошибок, не видно.
- «Check connection» говорит «успех» при неверном ключе: проверка ходит в незащищённый `GET /`.
- TestFlight требует платного Apple Developer (#14).

По ADR-0020 iPhone должен сузиться до насоса HealthKit; насос не реализован.

## 11. Импорт и экспорт personal-os — Готово — `imports/`, `exports/`

Personal-os — прежняя файловая система дня: markdown-планы, отчёты, итоги, недели, `goal.md`, состояние тренировок. Импорт переносит её в базу и повторяется без вреда. Неизменённые файлы пропускаются по хешу. Отметки привязываются по содержимому строки, а не по позиции. Вердикт берётся из прозы «День выигран?» и больше не пересчитывается. Каждый спорный случай попадает в отчёт.

Еженедельный экспорт пишет обратно те же `.md` по неделям — страховка отката. Сверка экспорта и обратного импорта сошлась на 13 днях.

**Чего нет.** Скиллы `/day-open` и `/day-close` ещё не переведены на API (#95). Числа правил всё ещё живут в трёх местах файловой системы (#153).

## 12. Сквозное

### 12.1 Вход и доступ — Готово

Сервер виден только внутри tailnet, публичного входа нет. Все ручки закрыты одним ключом. Браузер вводит ключ один раз на `/login` и получает подписанную куку на 30 дней; ключ в браузере не хранится, а сборка фронтенда проверяется на утечку ключа. iOS и агент шлют ключ заголовком `X-API-Key`. В проде сервер не стартует с пустым ключом, пустым секретом сессии или CORS `*`.

Отозвать одну сессию нельзя — только сменить секрет для всех. При этом станут нечитаемыми сохранённые ключи источников входящих.

### 12.2 Фоновые задания и деплой — Частично

Один воркер с двумя заданиями: пульс раз в 5 минут и ночной каркас раз в сутки. Каждое задание берёт блокировку в Postgres, двойной запуск невозможен. Опрос входящих и ретенция в реестр не добавлены. Бэкапы базы — cron хоста в 03:00, экспорт markdown и проверка восстановления — по понедельникам.

Деплой — `make preflight && make deploy` на сервере: обновление кода, сборка, проверка, миграции. Миграции запускаются после подъёма контейнеров, то есть новый код несколько секунд работает на старой схеме. Прод-контур с docker целиком ни разу не прогонялся в рамках PHASE-03 (#183).

### 12.3 Приватность

- Персональные данные не пишутся в логи: сервер логирует коды ошибок и id.
- Тела писем и сообщений не хранятся; заголовки окон по умолчанию отбрасываются.
- Секреты источников зашифрованы ключом, выведенным из секрета сессии.
- Распознавание речи — на устройстве.
- Личные данные трекера уходят в Anthropic при каждом AI-вызове — это принятое решение (ADR-0005).

## 14. Открытые вопросы

1. **Экран дня.** Вариант 1 (единый экран со связанными карточками) или 2 (отдельные экраны)? Без ответа тикеты на реализацию не заводятся. — #199.
2. **Цепочка миграций.** Для починки отката надо править начальную миграцию, а правила проекта это запрещают. Проверять только новые миграции или ждать архитектурного решения? — #181.
3. **Период AI-разбора по умолчанию.** 7 или 30 дней, свежесть отчёта 24 часа? — #80.
4. **Язык интерфейса.** PRD дашборда требует английский, #199 — русские названия действий. Какой?
5. **Агент на маке и прод.** Разрешить `http://` внутри tailnet или поднять HTTPS? — #155.
6. **Пункт плана и запись категории.** «Цель 300, сделано 100» — один факт в истории категории или два? Нужен ADR. — #200.
7. **Быстрая отметка и цель пункта.** Должна ли кнопка закрывать пункт «2 л воды» первым стаканом?
8. **Вечер с близкими.** Обязателен каждый день или только в выходные? Вердикт и правила плана сейчас отвечают по-разному.
9. **Роль iPhone.** Оставить девять вкладок или сузить до насоса HealthKit, как решил ADR-0020?
10. **LangChain.** ADR-0006 его выбрал, в коде его нет. Закрыть отдельным ADR?
11. **ClickUp.** Показывать задачи на сегодня или весь спринт?

| Правила как версии с датами | Прошлый день не пересчитывается задним числом при смене правил | 5.2 |
| Граница суток 04:00 | Поздний вечер принадлежит своему дню | 5.1 |
| Вердикт с причиной и переопределением с запиской | Видно, почему день проигран; честное исключение | 5.8 |
| «Не измерено» ≠ «ноль» | День без учёта времени не выглядит чистым или проигранным | 5.7 |
| Долг за переработку | Поднять потолок можно, но минуты придётся вернуть | 5.9 |
| Быстрые отметки с горячими клавишами и отменой | Один тап или клавиша; отмена с проверкой ручной правки | 6.1 |
| Челленджи с бюджетом промахов | «30 дней, можно пропустить 3» — честный счёт | 6.2 |
| Правила разметки с пробным прогоном | Видно, что поменяет правило, до сохранения | 7.1 |
| «Подтверждённое человеком не трогаем» | Автоматика не перетирает ручную правку | 1, 7.1 |
| Офлайн-очередь с ключом идемпотентности | Запись в зале без сети не теряется и не дублируется | 10.3 |
| Мобильная оболочка поверх тех же хуков | Два интерфейса, одна логика | 10.2 |
| Импорт по хешу и содержимому строки | Повторный импорт безопасен, отметки не съезжают | 11 |

## 16. Глоссарий

| Слово | Значение |
|---|---|
| **Категория** | То, что отслеживается: «Сон», «Вода». Набор полей, заданный человеком |
| **Поле** | Атрибут категории одного из восьми типов |
| **Запись** | Значения полей категории на дату |
| **Чек-лист** | Категория из флажков, одна запись на день |
| **Avoid / build** | Смысл серии: «избегаю» или «делаю». Считается только avoid |
| **Граница суток** | 04:00 по Берлину; всё до неё относится к предыдущему дню |
| **Канон, правила дня** | Версия `day_rule_set` с периодом действия: потолки, края, якоря, условия вердикта |
| **План дня** | Документ из секций и пунктов; заменяется целиком, проверяется целиком |
| **Пункт** | Строка плана: задача, якорь, жёсткая точка, свободный, минимум |
| **Жёсткость** | `hard` / `soft` / `free`; жёсткими бывают только края дня |
| **Якорь** | Обязательный край дня: подъём, спорт, старт работы, ревью, отбой, вечер с близкими |
| **Свободный вечер** | Окно, которое план не имеет права занимать |
| **Каркас (скелет)** | План из правил без модели; запасной путь |
| **Ревизия 0** | Снимок плана, предложенного машиной; от него считается диф |
| **Вердикт** | «Выигран / проигран» с причиной и списком условий |
| **Условие (клауз)** | Проверка вердикта: переработка, якоря, задачи, роль |
| **Профиль потолка** | baseline / deadline / recovery |
| **Долг** | Минуты сверх базового потолка; пока не погашен, неделя не выиграна |
| **Быстрая отметка** | Кнопка «в один тап», привязанная к полю |
| **Челлендж** | Обязательство на окно дат по паре «категория + поле» |
| **Роль, акт роли** | CTO, архитектор, тимлид; минуты — куда ушло время, акт — случилась ли роль |
| **Режим дня** | Работа, выходной, отпуск, больничный плюс флаг «без кода» |
| **Сигнал** | Конверт из ClickUp, Gmail или Telegram без тела |
| **Плашка** | Предложение чата с галочками; применяется одним нажатием |
| **Карточка дня** | Ограниченный контекст, который чат получает в каждом ходе |
| **Выборка** | Именованный запрос данных из белого списка, который чат может попросить |
| **Насос HealthKit** | Роль iPhone по ADR-0020: читать и отправлять сырые семплы |
| **personal-os** | Прежняя файловая система дня в markdown; перенесена в базу |
| **`/m`** | Мобильная оболочка веба, ставится как PWA |
