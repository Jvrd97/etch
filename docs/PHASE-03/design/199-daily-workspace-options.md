# Два варианта экрана ежедневной работы

**Тикет:** #199

**Дата:** 2026-09-11
**Статус:** подготовка к выбору; финальный вариант не выбран

## Цель

Экран дня должен позволять собрать план, записать факт и открыть ту же запись в истории категории без повторного ввода. Это дизайн-подготовка: она не меняет работающие сценарии и не подменяет выбор пользователя.

Основание — [исследование ежедневной работы](../../../research/2026-09-05-daily-workspace-design.md). Оно рекомендует первый вариант, но рекомендация не является решением.

## Общие правила

- Главным действием остаётся работа с текущим днём. Большие отчёты и подробности раскрываются только по запросу.
- Цель плана и сохранённый факт показаны отдельно. Генерация плана сама не создаёт запись в истории.
- При вводе факта карточка показывает выбранные категорию, поле и единицу. После сохранения доступен переход к той же записи и её исправление.
- Системные действия и ошибки названы по-русски. Введённый текст дня сохраняется при сбое разбора; сборка плана не владеет этим текстом.
- На телефоне блоки идут один под другим; на десктопе допустима правая колонка. Основные цели касания имеют размер не меньше 44×44 CSS-пикселей.

## Вариант 1: единый экран дня со связанными карточками

Это рекомендация исследования. План и ввод факта находятся в одном рабочем месте; история открывается из сохранённого результата.

### Desktop

```text
┌──────────────────── День: 11 сентября ────────────────────┐
│ План готов · 2 из 4 пунктов             [Пересобрать план] │
├───────────────────────────────────┬────────────────────────┤
│ План                              │ Быстрый ввод            │
│                                   │                        │
│ Отжимания                         │ Вода        [ +250 мл ] │
│ Цель: 300 повторений              │ Прогулка    [ +1 км ]   │
│ Сделано: [ 100 ] повторений [✓]   │ [Все категории]         │
│ [Открыть запись]                  │                        │
│                                   ├────────────────────────┤
│ Прогулка                          │ Обзор дня               │
│ Цель: 3 км                        │ 2 сделано · 1 частично  │
│ [Записать факт]                   │ [История категорий]     │
└───────────────────────────────────┴────────────────────────┘
```

### Телефон

```text
┌──────────────────────────┐
│ 11 сентября · План готов │
│ [Пересобрать план]       │
├──────────────────────────┤
│ Отжимания                │
│ Цель 300 повторений      │
│ Сделано [ 100 ] [Сохран.]│
│ [Открыть запись]         │
├──────────────────────────┤
│ Быстрый ввод             │
│ Вода [ +250 мл ]         │
│ [Все категории]          │
├──────────────────────────┤
│ 2 сделано · 1 частично   │
│ [История категорий]      │
└──────────────────────────┘
```

**Последствие:** один путь для плана и факта; потребуется надёжная связь пункта плана с записью категории из #200.

## Вариант 2: план и категории на отдельных экранах

План остаётся компактным списком. Карточка пункта ведёт к категории, где создаётся или исправляется запись.

### Desktop

```text
┌──────────────────── День: 11 сентября ────────────────────┐
│ План готов · 2 из 4 пунктов             [Пересобрать план] │
├───────────────────────────────────┬────────────────────────┤
│ План                              │ Обзор дня               │
│                                   │                        │
│ Отжимания · цель 300 повторений   │ 2 сделано · 1 частично  │
│ [Открыть категорию]               │ [Все категории]         │
│                                   │                        │
│ Прогулка · цель 3 км              │ Быстрый ввод             │
│ [Открыть категорию]               │ Вода [ +250 мл ]         │
└───────────────────────────────────┴────────────────────────┘
```

### Телефон

```text
┌──────────────────────────┐
│ 11 сентября · План готов │
├──────────────────────────┤
│ Отжимания · цель 300     │
│ [Открыть категорию]      │
├──────────────────────────┤
│ Прогулка · цель 3 км     │
│ [Открыть категорию]      │
├──────────────────────────┤
│ Быстрый ввод             │
│ [Все категории]          │
└──────────────────────────┘
```

**Последствие:** меньше изменений в экране дня, но ввод факта требует перехода и возврата. Этот вариант не соответствует основной гипотезе исследования, пока не доказано, что переход не мешает сценарию.

## Состояния плана, факта и быстрого ввода

| Состояние | Что видит пользователь | Доступное следующее действие |
| --- | --- | --- |
| Пустой день | Дата и краткое объяснение отсутствия плана. Быстрый ввод остаётся доступен, если есть активные категории; иначе явно показано, что активных категорий нет | «Собрать план», добавить факт вручную или открыть категории |
| Сборка плана: ожидание | «Собираем план для 11 сентября» и индикатор. Текст дня здесь не показывается и не сохраняется | Ждать завершения; состояние не выглядит ошибкой голосового ввода |
| Сборка плана: ошибка | Название неудавшейся операции и понятная причина, если она известна | Повторить, собрать без модели или продолжить работу с быстрым вводом |
| План готов | Пункты, цели, связанные категории и состояние выполнения | Записать факт, связать категорию или открыть подробности |
| Частичный результат | Отдельные цель и факт, например «цель 300, сделано 100» | Добавить ещё, исправить факт или оставить частичное выполнение |
| Отметка внесена | Подтверждение сохранения, время и ссылка на конкретную запись | Открыть историю или начать явное исправление значения |
| Отметка исправляется | Исходное значение, новое значение и явное действие сохранения | Сохранить изменение; до сохранения история не меняется |

## Состояния разбора дня

Разбор дня — отдельный поток. Успешный разбор предлагает факты к проверке, но не обещает, что записи уже сохранены.

| Состояние | Что видит пользователь | Доступное следующее действие |
| --- | --- | --- |
| Ввод голосом | Состояние микрофона и понятная ошибка доступа к микрофону, если она возникла | Продолжить голосом после исправления доступа или перейти к текстовому вводу |
| Ввод текстом | Текст дня в поле и действие «Разобрать день» | Отредактировать или начать разбор |
| Разбор: ожидание | «Разбираем текст дня», сохранённый текст и индикатор | Ждать; микрофонная ошибка не выдаётся за ошибку разбора |
| Разбор: результат | Сопоставленные категории, требующие выбора факты и оценённые значения | Проверить, выбрать категорию для несопоставленного факта и явно сохранить подтверждённые записи |
| Разбор: ошибка | Текст остаётся в поле, отдельно назван неудавшийся разбор и причина, если она известна | Повторить разбор или продолжить редактирование текста |

## Короткая проверка с пользователем

### До проверки

Записать на текущем интерфейсе число действий, время без ожидания сервера и затруднения. Затем показать оба низкодетализированных варианта на телефоне и десктопе в одинаковом порядке, чередуя первый показ между участниками, если их будет больше одного.

### Сценарии

1. Собрать день, записать 300 отжиманий и открыть созданную запись в категории.
2. Изменить 300 на 200 и убедиться, что открыта та же запись, а не создана новая.
3. Отметить простую булеву avoid-категорию и проверить понятное подтверждение сохранения.
4. Найти редкую категорию через полный список.
5. После ошибки разбора вернуться к сохранённому тексту и понять, что именно не удалось.
6. Удалить разговор и вернуться к текущей работе.

### Что записать

| Показатель | Цель для сравнения |
| --- | --- |
| Запись факта из плана | Без ухода с экрана в варианте 1; одна запись после перезагрузки |
| Булева отметка | Одно действие и понятное подтверждение сохранения |
| История мобильного чата | Открытие одним действием, выбор разговора ещё одним |
| Повтор после потери ответа | Нет дублей и потери ручных изменений |
| Ошибка разбора | Текст сохранён; ясно названа неудавшаяся операция |

Записать время, число действий, ошибки, непонятные подписи и замечания о клавиатуре, фокусе, контрасте, масштабе 200 % и узком экране. Улучшение нельзя объявлять без этого сравнения.
