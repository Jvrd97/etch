# ADR-0019: Локальный агент на macOS — сбор активности, плавающее окно, режимы дня

## Status

Принято (2026-08-30) — in-review. Номер согласован с пачкой ADR фазы PHASE-03
(0008–0014), нумерация внутри пачки правится при слиянии.

## Context

habit_tracker_ai становится рабочим местом дня: personal-os сливается в него,
план дня, итоги, вердикт «день выигран», тренировки и цели переезжают в Postgres,
а `plan_server.py`, `plan_html.py`, `life.py` и приложение в Dock уходят.
Основной интерфейс — существующий Next.js во вкладке браузера на маке.

Браузер четырёх вещей не может, и именно они держат день CTO:

1. **Он не знает, где прошло время.** Вкладка видит только себя. Сейчас
   «код за день» восстанавливается по `git log --since` за календарные сутки, и
   это уже дало дефект: коммит в 00:01 приписан следующему дню
   (`personal-os/feedback.md`, 2026-08-29). Задача, отмеченная сделанной без
   единого коммита, ловится только глазами в `/day-close`.
2. **Он не всегда виден.** Таймер и текущая задача во вкладке за Xcode — то же
   самое, что их отсутствие.
3. **Он не переживает офлайн.** VPS доступен только внутри tailnet (ADR-0003), в
   вебе service worker'а нет вообще, ноут бывает без сети.
4. **Он не переключает режим дня.** Сегодня режим no-code живёт в файле
   `~/.claude/nocode/config` (`days=2,4`, `override=YYYY-MM-DD:on|off`) и
   проверяется хуком; про выходной, отпуск и болезнь система не знает ничего.

Ограничения, которые заданы решениями человека и не обсуждаются: скриншотов не
делаем никогда; собираем только активное приложение и заголовок окна с интервалом
в секунды; ручной ввод первичен, автоматика — подсказка; режим переключается по
расписанию плюс ручным переключателем, автоопределение по активности отвергнуто;
копий веб-интерфейса в нативном приложении не делаем.

Два фактических ограничения среды. Первое: владелец — CTO медицинской компании,
и заголовок окна у него — это имя файла, домен, тема письма, иногда имя пациента;
заголовок ценнее всего и опаснее всего одновременно. Второе: в personal-os уже
проверено, что **launchd-агент не получает доступ к `~/Documents`**
(`Operation not permitted`, `docs/plan-app.md:182`, `tools/install_plan_app.sh:15`),
поэтому сервер плана живёт под `.app`, а не под launchd.

Что уже есть и на что опираемся: контур health (`app/api/health.py`,
`app/crud/health.py`) — приём сырья пачками, естественный ключ
`uq_health_hour_bucket_natural_key (metric_id, local_date, hour)` и
`ON CONFLICT DO UPDATE`, из-за которого `Idempotency-Key` в этом контуре не нужен
вовсе; локальный час как зерно данных вместо UTC; каталог метрик таблицей, а не
enum'ом. На iOS — `Cache/OutboxQueue.swift` (очередь `POST /entries`, автосброс по
`NWPathMonitor`) и `API/KeychainStore.swift`.

## Decision

Ставим один маленький нативный агент **`HabitAgent.app`** на Swift/SwiftUI
(macOS 14+, XcodeGen, без внешних зависимостей), который делает ровно четыре
вещи: пишет интервалы активности, показывает плавающее окно поверх всех
приложений, держит переключатель режима дня и считает агрегаты по сессиям Claude
Code. Копий веб-экранов в нём нет.

Конкретно:

- **Источник активности** — `NSWorkspace.didActivateApplicationNotification` для
  смены приложения плюс таймер 5 с для заголовка и простоя. Заголовок берётся
  **только через Accessibility API** (`AXUIElementCreateApplication` →
  `kAXFocusedWindowAttribute` → `kAXTitleAttribute`).
  `CGWindowListCopyWindowInfo` не используем никогда, поэтому разрешение Screen
  Recording не запрашивается ни разу. Простой считается
  `CGEventSourceSecondsSinceLastEventType` (разрешений не требует, самих нажатий
  не видит). Экран заблокирован или мак уснул — сбор останавливается.
- **Приватность заголовков — default deny.** Правило приватности применяется
  **на маке, до записи в очередь**: то, что запрещено, физически не покидает
  устройство. Незнакомое приложение получает действие `drop` — на сервер уходит
  только bundle id. Правила лежат в БД и тянутся агентом (`GET /agent/config`),
  но их применение — на клиенте.
- **Единица данных — интервал**, не отсчёт. Соседние отсчёты одного приложения
  склеиваются, разрыв меньше 30 с не рвёт интервал, а считается переключением
  (`switch_count`). Пачка интервалов уходит `POST /api/v1/agent/activity` и
  делает upsert по естественному ключу `(source, started_at, app_id)` — тот же
  приём, что в health, без `Idempotency-Key`.
- **Ручной ввод первичен.** Авто-интервал правится постфактум (`PATCH`), при этом
  остаётся `source='agent'` и получает `is_corrected=true`; запись руками — новый
  интервал `source='manual'` без всякого приложения. Пересечения разрешены, а
  время по задаче считается **длиной объединения диапазонов** (`range_agg` по
  `tstzrange`), а не суммой строк, поэтому ручная запись поверх авто не удваивает
  час.
- **Плавающее окно** — `NSPanel` (`.nonactivatingPanel`, `level = .floating`,
  `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`), перетаскивается
  за любое место, помнит кадр (`setFrameAutosaveName`), сворачивается в
  `MenuBarExtra`. В нём: текущая задача, таймер, переключатель режима и до
  четырёх быстрых отметок. Содержание отметок проектирует тема
  challenges-and-quick-marks; окно знает только контракт
  `GET /api/v1/today/quick-marks` → `[{id, label, glyph, unit, step}]` и
  `POST /api/v1/today/quick-marks/{id}`; пятая и далее — кнопка «ещё», которая
  открывает браузер.
- **Режим дня — два ортогональных измерения**, потому что в `config.md` вторник
  одновременно рабочий и no-code: `kind` (`work|dayoff|vacation|sick`) и
  `nocode` (bool). Расписание в таблице `mode_schedule` (7 строк сида), ручной
  переключатель пишет строку `day_mode` на дату и перебивает расписание.
  Автоопределения по активности нет.
- **Метрики Claude Code считаем по `~/.claude/projects/**/*.jsonl`**, а не по
  времени в окне терминала. На сервер уходят только агрегаты: `session_uid`,
  `cwd`, `git_branch`, границы времени, число ходов, токены, модель, первая
  строка цели из `~/.claude/statusline/goals/<session_id>`. Сами транскрипты
  (1.1 ГБ, 2282 файла, внутри — код и переписка) не покидают мак никогда.
  Для VSCode локальных данных о времени нет: `state.vscdb` — недокументированный
  внутренний KV; берём время в приложении общим механизмом.
- **Доставка** — очередь на диске (SwiftData в
  `~/Library/Application Support/com.talvior.habitagent/`), флаш по
  `NWPathMonitor`, экспоненциальный бэкофф, батч не больше 500 интервалов.
  Аутентификация — тот же `X-API-Key` из Keychain (ADR-0003), сеть — tailnet.
- **Запуск** — `.app` в `~/Applications`, автозапуск через
  `SMAppService.mainApp.register()`, `LSUIElement = true`. **Не launchd-агент.**
  Агент не читает и не пишет ничего в `~/Documents` и в репозиторий.

## Options considered

### Развилка 1. Чем брать заголовок окна

#### Вариант A: Accessibility API (`AXUIElement`) — выбран
- **Описание**: доверие процессу выдаётся один раз в Системных настройках,
  заголовок фокусного окна читается напрямую.
- **Плюсы**: одно разрешение вместо двух; Screen Recording не запрашивается
  никогда, а значит человеку не приходится давать право на снимок экрана
  системе, которая обещала скриншотов не делать.
- **Минусы**: часть приложений (Electron, старые Carbon) отдаёт пустой или
  мусорный `AXTitle`; отзыв разрешения молча превращает заголовки в `nil`.
- **Выбран потому, что**: обещание «скриншотов нет» должно быть проверяемо
  списком разрешений, а не доверием к коду.

#### Вариант B: `CGWindowListCopyWindowInfo` с `kCGWindowName`
- **Плюсы**: видит заголовки всех окон, не только фокусного.
- **Минусы**: с macOS 10.15 требует **Screen Recording**; в системном списке
  агент оказывается рядом с записывающими экран программами.
- **Отвергнут потому, что**: просить право на запись экрана у системы, которая
  принципиально не делает скриншотов, — противоречие, которое придётся
  объяснять каждый раз при обновлении macOS.

#### Вариант C: только имя приложения, заголовков нет
- **Плюсы**: ноль разрешений, ноль риска утечки.
- **Минусы**: «4 ч в Chrome» — не факт о дне. Отличить ClickUp от YouTube нечем,
  а связать интервал с задачей — тем более.
- **Отвергнут потому, что**: это и есть урезанный режим, в который агент падает
  сам при отсутствии разрешения; делать его единственным — терять смысл сбора.

### Развилка 2. Зерно данных

#### Вариант A: интервалы с естественным ключом `(source, started_at, app_id)` — выбран
- **Плюсы**: переживает правку постфактум («на самом деле 1.5 ч») сдвигом
  границы; повторная присылка того же интервала перезаписывает строку, как в
  health; ручная запись живёт в той же таблице.
- **Минусы**: пересечения возможны, суммой строк время считать нельзя.
- **Выбран потому, что**: пересечение лечится одним запросом `range_agg`, а
  отсутствие ручной правки не лечится ничем.

#### Вариант B: почасовые корзины, как `health_hour_buckets`
- **Плюсы**: идентичен уже работающему контуру, дешёвая свёртка по дню.
- **Минусы**: «переназначь эти 40 минут задаче X» в корзину не ложится; час —
  слишком грубо для дня, где переключений десятки.
- **Отвергнут потому, что**: ручной ввод объявлен первичным, а корзина его не
  выражает.

#### Вариант C: сырые отсчёты раз в 5 секунд на сервере
- **Плюсы**: клиент тупой, вся логика склейки на сервере (как в health).
- **Минусы**: 17 280 строк в сутки против ~300; и главное — сырьё здесь не
  безобидные шаги, а поток заголовков, который придётся хранить целиком.
- **Отвергнут потому, что**: чем меньше сырья уезжает с мака, тем меньше цена
  ошибки в правилах приватности.

### Развилка 3. Метрики Claude Code

#### Вариант A: разбор `~/.claude/projects/**/*.jsonl` на маке, на сервер — агрегаты — выбран
- **Описание**: проверено фактически: в записи `assistant` есть `timestamp`,
  `cwd`, `gitBranch`, `message.model`, `message.usage` с `input_tokens`,
  `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, а
  также `version` и `effort`. Цель сессии — файл
  `~/.claude/statusline/goals/<session_id>`, первая строка = заголовок.
- **Плюсы**: считает работу, а не присутствие; различает проекты по `cwd` и
  ветку по `gitBranch`; ловит фоновые запуски `claude -p` без окна.
- **Минусы**: формат приватный и недокументированный, поля меняются между
  версиями CLI (видели 2.1.246 и 2.1.250 в одном дне); полный обход 1.1 ГБ
  дорог, нужен инкремент по mtime и смещению.
- **Выбран потому, что**: время в окне терминала не отличает «Клод работает» от
  «я читаю почту в соседней вкладке», а это ровно та подмена, из-за которой
  «90% написал Клод» и появилось.

#### Вариант B: время в окне терминала
- **Плюсы**: ноль парсеров, работает механизмом сбора активности.
- **Минусы**: не видит фоновых сессий, считает простой, не знает проекта.
- **Отвергнут потому, что**: даёт число, которому нельзя верить, — худший из
  возможных исходов для метрики роли.

#### Вариант C: отправлять `.jsonl` на сервер и разбирать там
- **Отвергнут потому, что**: внутри транскриптов — код Talvior и личная
  переписка; ни одного сценария, где это нужно на сервере, нет.

### Развилка 4. Язык и упаковка

#### Вариант A: Swift/SwiftUI, XcodeGen, без зависимостей — выбран
- **Плюсы**: владелец уже пишет на Swift для iOS-клиента этого же проекта;
  `NSPanel` поверх фуллскрина, `AXUIElement`, `SMAppService`, `NWPathMonitor` и
  SwiftData — всё из SDK; сборка и тесты те же, что у iOS (`xcodebuild test`,
  XCTest); одна и та же модель офлайн-очереди, что в `Cache/OutboxQueue.swift`.
- **Минусы**: третий клиент в репозитории; feedback loop проекта
  (`mypy --strict`, `ruff`) на Swift не распространяется.
- **Выбран потому, что**: чинить это придётся в одиночку, а Swift — язык, на
  котором в этом же репозитории уже лежит работающий клиент.

#### Вариант B: Python + rumps
- **Плюсы**: язык бэкенда, быстрый старт, `uv` уже в проекте.
- **Минусы**: AX-доступ только через pyobjc-обвязку; `NSPanel` с
  `.fullScreenAuxiliary` через rumps не выражается; упаковка в подписанный
  login item (py2app + встроенный интерпретатор) ломается на каждом обновлении
  macOS; TCC-разрешение выдаётся интерпретатору, а не приложению.
- **Отвергнут потому, что**: чинить упаковку в одиночку дороже, чем написать
  окно на SwiftUI.

#### Вариант C: Hammerspoon / скрипт на Lua
- **Плюсы**: сбор активности пишется за вечер.
- **Минусы**: очередь, ретраи, Keychain и окно всё равно писать; третий язык в
  доме; зависимость от чужого приложения, которое само требует разрешений.
- **Отвергнут потому, что**: экономит только самую простую часть работы.

#### Вариант D: Electron
- **Отвергнут потому, что**: 100+ МБ и отдельный браузер ради таймера, при том
  что браузер и так открыт.

### Развилка 5. Автозапуск

#### Вариант A: `.app` в `~/Applications` + `SMAppService.mainApp` — выбран
- **Плюсы**: TCC-разрешения выдаются бандлу и переживают обновления; человек
  видит агент в «Объектах входа» и снимает одной галкой; в personal-os этот путь
  уже проверен на приложении «План дня».
- **Минусы**: обновление — перезапись бандла руками (пока нет Sparkle).
- **Выбран потому, что**: launchd в этом доме уже проверен и не работает.

#### Вариант B: launchd LaunchAgent
- **Отвергнут потому, что**: `docs/plan-app.md:182` и комментарий в
  `tools/install_plan_app.sh:15` фиксируют фактом: фоновому агенту macOS не даёт
  доступа, в логе `Operation not permitted`. Отдельно: launchd-процессу неудобно
  показывать TCC-запрос — окно разрешения принадлежит приложению.

## Модель данных

Шесть новых таблиц. `user_id` нет ни в одной — граница многопользовательности
описана ниже отдельно.

### `tracked_app` — каталог приложений

Таблица, а не enum: научить систему новому приложению должно стоить строку, а не
миграцию (тот же довод, что у `health_metrics`).

| поле | тип | примечание |
|---|---|---|
| id | Integer PK | |
| bundle_id | String(200) UNIQUE NOT NULL | `com.microsoft.VSCode` |
| display_name | String(120) NOT NULL | |
| category | String(30) NOT NULL default `'other'` | `code\|browser\|comms\|terminal\|design\|other` — обычная строка, не PG-enum |
| title_policy | String(10) NOT NULL default `'drop'` | `keep\|mask\|drop` — **default deny** |
| is_work | Boolean NULL | троичное, как `categories.show_in_today`: NULL = решает режим дня |
| created_at, updated_at | DateTime(tz) | |

### `title_rule` — правила приватности заголовков

Применяются на маке, хранятся на сервере, чтобы правились из веба и переживали
переустановку агента.

| поле | тип | примечание |
|---|---|---|
| id | Integer PK | |
| ord | Integer NOT NULL | порядок применения, первое совпавшее выигрывает |
| match_kind | String(20) NOT NULL | `bundle_id\|bundle_prefix\|title_regex` |
| pattern | String(300) NOT NULL | |
| action | String(10) NOT NULL | `keep\|mask\|drop` |
| note | Text NULL | зачем правило существует |
| is_active | Boolean NOT NULL default true | |

Сид миграции (дублируется в теле миграции, как `SEED_METRICS` в
`health_contour_tables`): `drop` для менеджера паролей (`com.1password.*`,
`com.apple.keychainaccess`), банковских и медицинских приложений и для всего,
что не совпало ни с одним правилом; `mask` для браузеров (от заголовка остаётся
только домен) и редакторов (остаётся только расширение файла и имя репозитория);
`keep` — точечно, по явному решению человека.

### `activity_interval` — интервал активности

| поле | тип | примечание |
|---|---|---|
| id | BigInteger PK | |
| source | String(10) NOT NULL | `agent\|manual` |
| app_id | Integer NULL FK `tracked_app.id` ON DELETE RESTRICT | NULL у ручной записи |
| started_at | DateTime(tz) NOT NULL | |
| ended_at | DateTime(tz) NOT NULL | CHECK `ended_at >= started_at` |
| duration_seconds | Integer GENERATED ALWAYS AS `EXTRACT(EPOCH FROM ended_at - started_at)::int` STORED | длительность — производная границ, разъехаться не может |
| local_date | Date NOT NULL | календарь, который прожил человек (приём health) |
| utc_offset_minutes | Integer NOT NULL | |
| title | Text NULL | уже нормализован на маке |
| title_source | String(10) NOT NULL | `full\|masked\|dropped` — честно говорит, что стало с заголовком |
| idle_seconds | Integer NOT NULL default 0 | сколько внутри интервала не было ввода |
| switch_count | Integer NOT NULL default 0 | микропереключений внутри интервала |
| plan_task_id | BigInteger NULL | FK на задачу дня появится срезом после day-in-postgres |
| clickup_task_id | String(40) NULL | |
| is_corrected | Boolean NOT NULL default false | |
| corrected_at | DateTime(tz) NULL | |
| note | Text NULL | |
| created_at, updated_at | DateTime(tz) | |

Ограничения и индексы:

- `uq_activity_interval_natural` UNIQUE `(source, started_at, app_id)` — цель
  `ON CONFLICT DO UPDATE`. Повторная присылка пачки после обрыва связи
  перезаписывает строку и ничего не удваивает.
- `ix_activity_interval_local_date` на `local_date`;
  `ix_activity_interval_day_app` на `(local_date, app_id)`;
  `ix_activity_interval_task` на `plan_task_id`.
- Ручные записи `source='manual'` имеют `app_id IS NULL`; в Postgres NULL в
  уникальном ключе различны, поэтому две ручные записи с одинаковым началом
  не схлопываются — и не должны: человек вправе записать два дела в одно окно
  времени. Идемпотентность ручной записи даёт существующий заголовок
  `Idempotency-Key` (прецедент — `entries.idempotency_key`).
- **Время по задаче считается длиной объединения диапазонов**:
  `SELECT range_agg(tstzrange(started_at, ended_at))` с последующим суммированием
  длин, а не `SUM(duration_seconds)`. Это единственное место, где решается
  пересечение ручного и автоматического.

### Миграция

Одна ревизия Alembic `phase03_mac_agent_tables`, `down_revision` — голова на
момент реализации (сейчас `a7c9e1b3d5f8`; если срезы day-in-postgres уедут
раньше, цепочка остаётся линейной). Содержимое: шесть `create_table`, три
уникальных ограничения, четыре индекса, `Computed()` на `duration_seconds`,
CHECK на `weekday` и на `ended_at >= started_at`, и три сида (`mode_schedule` —
7 строк, `title_rule` — базовый набор, `tracked_app` — приложения из повседневного
набора). Сиды спеллятся в теле миграции заново, а не импортируются из `app/` —
миграция обязана значить то же, что в день применения. `downgrade()` роняет
таблицы в обратном порядке. Тестовая БД строится `create_all`, поэтому сиды в
тестах отсутствуют — как у health, лечится функцией `seed_*` из `app/crud/`.

## Consequences

### Что становится проще

- «Где прошёл день» перестаёт быть вопросом к памяти: `/day-close` получает
  интервалы вместо одного `git log --since`, и «отметка сделано без коммитов»
  ловится запросом, а не глазами.
- Работа сверх плана (Payment-сервис 28.08) видна в тот же час, а не из вечернего
  блокнота: интервал без задачи — это отдельная строка на экране дня.
- Таймер и текущая задача видны всегда, включая полноэкранный Xcode.
- Режим дня становится данными: `nextday` и критерий «день выигран» читают
  `day_mode`, а не расписание, зашитое в промпт.
- Обещание «скриншотов нет» проверяется списком разрешений macOS, а не доверием.

### Что становится сложнее

- Третий клиент в репозитории и второй язык сборки: `make check` его не
  покрывает, нужен `xcodebuild test` в feedback loop и своя строка в
  `SESSION_REVIEW.md`.
- Появляется состояние, которое живёт вне БД: очередь на маке. Отладка «почему
  вчерашних интервалов нет» теперь требует смотреть `queue_depth` в heartbeat.
- Правила приватности — код, который надо тестировать как бизнес-логику:
  ошибка в regex это не баг вёрстки, а тема письма на VPS.
- Ручная правка вводит второй источник истины на одном отрезке времени; каждый
  новый отчёт обязан считать через объединение диапазонов, и это легко забыть.
- Разбор `.jsonl` завязан на приватный формат Anthropic и будет ломаться.

### Какие риски приняли

- **Утечка заголовка.** Ошибка в правиле = имя файла пациента на VPS.
  Смягчение: default deny, применение правил на маке до записи в очередь,
  отдельный рубильник `titles_enabled`, и экран «сухой прогон» — что уйдёт на
  сервер за последний час — до первого включения отправки.
- **Отзыв разрешения.** Человек снял Accessibility — заголовков нет. Агент
  обязан продолжать слать интервалы с `title_source='dropped'` и
  `accessibility_granted=false`, а веб — показывать баннер. Падение здесь
  запрещено.
- **Формат Claude Code меняется.** Парсер считает только по записям `assistant` с
  `message.usage` и `timestamp`, незнакомые типы пропускает; ноль распознанных
  записей при непустом файле уходит в `last_error`, а не в тишину.
- **Два определения суток.** В проекте уже расходятся `entries.entry_date` (UTC)
  и `health_hour_buckets.local_date` (локальный). Агент присылает
  `utc_offset_minutes` и `local_date` по стенным часам; «день» с границей по
  подъёму и отбою — забота темы day-in-postgres, и до её решения свёртки по
  `local_date` дают календарные сутки.
- **Батарея.** Опрос 5 с; при простое дольше 60 с период растёт до 30 с; при
  блокировке экрана сбор останавливается.
- **Ad-hoc подпись.** Приложение не нотаризовано; при обновлении macOS
  TCC-разрешение может слететь и его придётся выдать заново.

### Что явно не решаем

- Многопользовательность (см. границу ниже).
- Второй мак: `agent_id` в схеме есть, слияние интервалов двух устройств — нет.
- Автоопределение режима по активности — отвергнуто человеком.
- Скриншоты, OCR, запись экрана, кейлоггинг — не будет никогда.
- Бот-выход в Telegram, входящие письма, генерация плана — другие темы.
- История версий агента и авто-обновление (Sparkle) — после первого рабочего
  месяца.
- Ретеншен интервалов: при ~300 интервалах в день это ~110 тысяч строк в год,
  чистка не нужна и не делается.

## Граница многопользовательности

`user_id` не заводим — как и во всех девяти существующих таблицах. Но граница
проходит по трём конкретным местам, и они выбраны так, чтобы второй пользователь
стоил одной миграции, а не переписывания:

1. **Ключ — уже носитель личности.** `X-API-Key` выдаётся устройству; второй
   пользователь = второй ключ, и `require_api_key` превращается в
   `resolve_user_by_key`, не меняя ни одного роутера.
2. **`agent_heartbeat.agent_id` уже существует.** Схема с самого начала допускает
   несколько агентов; сегодня их один, завтра — привязка `agent_id → user_id`.
3. **Естественные ключи не глобальны по смыслу.**
   `(source, started_at, app_id)` и `session_uid` при добавлении `user_id`
   расширяются до `(user_id, …)` одной миграцией; в отличие от
   `categories.name`, который уникален глобально и станет проблемой.

Чего сознательно **не** делаем: не добавляем `user_id` «на будущее» пустой
колонкой — она немедленно начнёт врать в запросах и индексах.

## Медицинские и личные данные

**Не покидает мак никогда**: снимки экрана (не делаются вовсе), содержимое окон,
буфер обмена, нажатия клавиш (считается только время с последнего события,
`CGEventSourceSecondsSinceLastEventType`), тексты сессий Claude Code, содержимое
и пути файлов VSCode, заголовки приложений из `drop`-списка и заголовки любого
приложения, которого нет в каталоге.

**Уходит на сервер**: bundle id и имя приложения, границы интервала и локальная
дата, смещение часового пояса, секунды простоя, число переключений, заголовок —
только если правило дало `keep` или `mask`, и признак `title_source`, по которому
всегда видно, что с заголовком сделали. По Claude Code — только числа, `cwd`,
ветка и цель сессии.

**Медицинские данные Talvior не попадают по построению**: медсистемы и
внутренние сервисы стоят в `drop`, а незнакомое приложение получает `drop` по
умолчанию — не попасть можно только явным решением человека внести приложение в
каталог с `keep`. Заголовок не логируется на сервере ни на одном уровне: правило
«никаких PII в логах» из `.claude/CLAUDE.md` §3 распространено в этом проекте на
тексты пользователя (`echo=False` у движка, `transcripts` мимо логов), и
`activity_interval.title` попадает в тот же класс.

## Как проверить, что сделано правильно

| Решение | Проверка |
|---|---|
| Скриншотов нет, Screen Recording не нужен | Системные настройки → Конфиденциальность → «Запись экрана»: `HabitAgent` в списке отсутствует, при этом заголовки собираются |
| Заголовки по умолчанию не уходят | новое приложение, не заведённое в `tracked_app`: интервал приходит, `title IS NULL`, `title_source='dropped'` |
| Правила применяются на маке | tcpdump/прокси на tailnet-интерфейсе либо лог тела запроса на сервере: в теле нет заголовка, который правило запретило |
| Работа без Accessibility | снять галку в Настройках → агент не падает, интервалы идут, heartbeat `accessibility_granted=false`, в вебе баннер |
| Идемпотентность доставки | послать одну пачку дважды: `buckets`/`intervals_written` тот же, `SELECT count(*)` не меняется |
| Офлайн | выключить Wi-Fi на час, работать, включить: интервалы за этот час на месте, `queue_depth` вернулся к нулю |
| Ручной ввод первичен | авто-интервал 2 ч в VSCode → правка на 1.5 ч по задаче X → в свёртке дня по задаче ровно 1.5 ч, `is_corrected=true` |
| Пересечения не удваивают | ручная запись 10:00–12:00 поверх авто 10:30–11:00 → время по задаче 2 ч, не 2.5 ч |
| Окно поверх фуллскрина | Xcode в полноэкранном режиме → окно видно; переход между Spaces → окно едет следом; перезапуск → позиция та же |
| Режим перебивает расписание | вторник, ручной переключатель в `vacation` → `GET /day-mode/<дата>` отдаёт `vacation`, `source='manual'`; на следующий день снова расписание |
| Claude Code считается по логам | запустить `claude -p` без окна терминала на переднем плане → сессия появилась в `claude_session` с ненулевыми токенами |
| Автозапуск | перезагрузка → агент в меню-баре, `SMAppService.mainApp.status == .enabled`, в логе нет `Operation not permitted` |
| Батарея | Activity Monitor, средний Energy Impact агента ниже 1.0 за рабочий день |

## Reversal cost

**Medium (1–2 недели).** Агент выбрасывается целиком без следа: он ничего не
пишет в репозиторий и держит своё состояние в
`~/Library/Application Support/`. Что остаётся — шесть таблиц и восемь ручек;
`activity_interval` при этом продолжает работать в ручном режиме из веба, потому
что `source='manual'` не зависит от агента вообще. Дороже всего откатывать
`title_policy`: если правила окажутся слишком щедрыми, придётся чистить уже
уехавшие заголовки (`UPDATE activity_interval SET title=NULL` по правилу) —
поэтому default deny с самого начала, а не «сначала соберём, потом разберёмся».

Сигнал пересмотреть решение: если за первый месяц доля интервалов с
`plan_task_id IS NULL` не опускается ниже половины — привязка ко времени задач
не работает, и вместо агента дешевле таймер руками.

## Notes

Проверено фактически, а не по памяти: в `~/.claude/projects` 59 каталогов
проектов, 2282 файла `.jsonl`, 1.1 ГБ; запись `assistant` несёт `timestamp`,
`cwd`, `gitBranch`, `message.model`, `message.usage` и `version`; цели сессий
лежат по `~/.claude/statusline/goals/<session_id>` (первая строка — заголовок для
статус-бара), рядом `~/.claude/statusline/labels/<session_id>` с коротким именем
окна. У VSCode `~/Library/Application Support/Code/User/History/*/entries.json`
хранит timestamp каждого сохранения файла (595 папок, формат
`{"version":1,"resource":"file://…","entries":[{"id","timestamp"}]}`) — дешёвый
и стабильный признак «реально правил файл», но `resource` это полный путь, то
есть та же приватная поверхность, что и заголовок окна. Поэтому источник
History остаётся отдельным тикетом за выключенным по умолчанию флагом, а в
первом срезе VSCode считается общим механизмом активности.
